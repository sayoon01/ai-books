# 생성 견고성(robustness) 개선 — 나중에 할 일

> 상태: **미구현 (보류)**. 2026-06-18 논의 정리. 지금은 `keep_alive="30m"`만 적용된 상태.

## 배경 — 무슨 문제가 있었나

PLAN으로 3권 재생성 중 **ollama 모델 런너가 "Stopping..." 상태로 내려가면서 요청이 무한 대기**에 빠져 1시간 넘게 멈춤.

### 원인 (3가지가 겹침)
1. **ollama 기본 `keep_alive=5분`** — 유휴 5분 뒤 모델을 메모리에서 언로드.
2. **in-flight 요청 중 클라이언트를 강제 종료(`kill -9`)** — 런너가 어정쩡한 상태가 되고, 곧 언로드 전환. 그 순간 새 요청이 내려가는 런너에 걸림.
3. **`ollama.chat()`에 타임아웃 없음** — 서버가 응답 안 주면 에러도 없이 **영원히 대기** (그래서 1시간째 멈춤).

### 이미 적용한 임시 대책
- `book_writer.py`: `_KEEP_ALIVE = "30m"` 추가, `_call`/`call_structured`의 `ollama.chat(..., keep_alive=_KEEP_ALIVE)`.
  → 챕터 사이 언로드 레이스를 막아 재발 방지. (근본 해결은 아래 A 필요)

---

## 제안 설계 (A + B + C 함께)

핵심: **"재시도"와 "건너뛰기"와 "이어가기"는 서로 다른 3개 층위**다.

### A. LLM 호출 단위 timeout + retry  ← 근본 해결
`generator/book_writer.py`의 `_call()`, `call_structured()` 두 곳.

- `ollama.chat()` 호출에 **timeout=600s** 적용 (호출이 무한 대기에 빠지지 않게).
  - 구현 옵션: `ollama.Client(timeout=600)`를 쓰거나, 호출을 스레드/시그널로 감싸 타임아웃. (ollama 파이썬 클라가 `timeout` 인자를 지원하면 그걸 사용)
- 타임아웃/예외 발생 시 **retry=3** 까지 같은 호출 재시도 (지수 백오프 선택).
- `call_structured`는 이미 검증 실패용 `retries`가 있음 — **타임아웃/연결오류도 같은 재시도 루프에 포함**시킬 것.

> 이게 빠져서, 호출이 멈추면 챕터 단위 `except`까지 도달조차 못 했음.

### B. 챕터 단위 실패 시 flagged 저장 후 continue
`generate()` 루프. (지금도 `ConvergenceError`는 잡아 continue 中 — 확장만)

- A의 재시도까지 모두 실패한 챕터는 **`chapter-NN.flagged.md`** (또는 `unit-NN.flagged.md`)로 저장 + 로그에 사유.
- `continue`로 다음 챕터 진행 → **전체 중단 없음**.
- 결과 예: 23챕터 중 **22 성공 + 1 flagged**.
- ⚠️ flagged된 챕터는 **그 실행 안에서는 다시 안 만듦** (= 건너뜀). 재생성은 C로.

### C. resume(이어가기) 모드  ← "실패한 1개만 다시"
재실행 시 **이미 정상 생성된 챕터는 스킵하고, 없는/flagged 챕터만** 다시 생성.

```
재실행 → chapter-01~07 정상 → 스킵
       → chapter-08 없음/flagged → 이것만 재생성
```

- 22개를 재작업하지 않고 **실패한 1개만 골라 재시도** = "다시 재시도"의 올바른 형태.
- 구현: `--resume` 플래그. 출력 폴더의 기존 `chapter-NN*.md` 존재 여부로 스킵 판정 (flagged는 미완료로 간주).

---

## 자주 한 오해 정리
- **"flagged+continue면 중간에 끊기는 것 아니냐?"** → 아니다. `continue`가 곧 "끊지 말고 다음으로". 끊김은 `raise`일 때.
- **"그럼 실패한 1개는 영영 재시도 안 되냐?"** →
  - 같은 호출은 A(retry=3)로 재시도됨.
  - flagged 챕터는 그 run에선 스킵, **C(resume)로 다음 실행 때 그것만 재생성**.

## 수용 기준
- 런너가 죽어도 무한 대기 없이 해당 호출만 타임아웃→재시도.
- 한 챕터가 끝내 실패해도 나머지 전부 생성 완료 (N-1/N 확보).
- `--resume` 재실행으로 실패분만 채워 최종 N/N 달성.
