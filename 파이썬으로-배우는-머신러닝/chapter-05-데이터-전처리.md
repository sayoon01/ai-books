# 5. 데이터 전처리

## 이번 장에서 배우는 내용

머신러닝 모델의 성능을 결정짓는 것은 화려한 알고리즘보다 **'데이터의 품질'**인 경우가 훨씬 많습니다. 아무리 뛰어난 요리사(모델)라도 재료(데이터)가 썩어 있거나 손질되지 않았다면 훌륭한 요리를 만들어낼 수 없습니다.

현실 세계의 데이터는 매우 지저분합니다. 값이 비어 있기도 하고(결측치), 말도 안 되게 크거나 작은 값이 섞여 있으며(이상치), 컴퓨터가 이해하지 못하는 문자열 형태로 되어 있기도 합니다. 이러한 데이터를 모델이 학습할 수 있는 최적의 형태로 가공하는 과정을 **'데이터 전처리(Data Preprocessing)'**라고 합니다.

이번 장에서는 머신러닝의 필수 관문인 데이터 전처리의 핵심 기법들을 배웁니다.

*   **결측치 처리**: 비어 있는 데이터를 어떻게 채우거나 제거할 것인가?
*   **이상치 처리**: 데이터의 흐름을 방해하는 튀는 값을 어떻게 처리할 것인가?
*   **피처 스케일링**: 서로 다른 단위의 숫자 데이터를 동일한 기준으로 맞추는 정규화와 표준화.
*   **범주형 데이터 인코딩**: 문자열 데이터를 컴퓨터가 계산할 수 있는 숫자로 바꾸는 방법.
*   **전처리 파이프라인**: 실무에서 효율적으로 전처리를 적용하는 흐름.

## 실생활 비유: 요리 전 '재료 손질'

여러분이 맛있는 찌개를 끓이려고 시장에서 재료를 사 왔다고 상상해 보세요.

시장에서 사 온 재료를 그대로 냄비에 넣으시겠습니까? 아마 아닐 것입니다.
*   **결측치 처리**: 썩은 부분은 도려내고, 부족한 재료는 다른 것으로 대체합니다.
*   **이상치 처리**: 너무 거대한 무 조각이 있다면 적당한 크기로 자르거나, 도저히 먹을 수 없는 이물질은 버립니다.
*   **피처 스케일링**: 소금 한 숟가락과 물 한 컵은 양의 단위가 다릅니다. 이를 '간'이라는 하나의 기준에 맞춰 조절해야 맛이 균형 잡힙니다.
*   **인코딩**: '매운맛', '순한맛'이라는 추상적인 맛의 종류를 '고춧가루 3스푼', '고춧가루 1스푼'이라는 구체적인 양(숫자)으로 변환하여 넣습니다.

이처럼 재료를 깨끗이 씻고, 다듬고, 양을 맞추는 **'재료 손질'** 과정이 끝나야 비로소 요리(모델 학습)를 시작할 수 있습니다. 데이터 전처리는 바로 머신러닝을 위한 재료 손질 과정입니다.

## 개념 설명: 왜 전처리가 필요한가?

### 1. Garbage In, Garbage Out (GIGO)
"쓰레기가 들어가면 쓰레기가 나온다"는 뜻입니다. 모델이 아무리 복잡하고 정교해도, 입력 데이터에 오류가 많거나 편향되어 있다면 모델은 잘못된 패턴을 학습하게 됩니다.

### 2. 모델의 수학적 특성
머신러닝 모델은 내부적으로 거대한 수학 계산기입니다.
*   **숫자만 이해함**: "서울", "부산" 같은 문자열은 계산할 수 없습니다. $\rightarrow$ **인코딩 필요**
*   **단위에 민감함**: '나이(0~100)'와 '연봉(0~수억)'이 함께 있으면, 모델은 숫자가 큰 연봉이 훨씬 더 중요한 정보라고 착각합니다. $\rightarrow$ **스케일링 필요**
*   **빈 값에 취약함**: 수학 식에 `NaN`(Not a Number)이 들어가면 결과는 모두 `NaN`이 됩니다. $\rightarrow$ **결측치 처리 필요**

---

## 기술 설명: 전처리의 4대 핵심 기법

### 1. 결측치(Missing Value) 처리
데이터가 누락된 상태를 말합니다.
*   **제거(Deletion)**: 결측치가 너무 많은 행이나 열을 삭제합니다. (데이터 손실 위험)
*   **대체(Imputation)**: 평균값, 중앙값, 최빈값 등으로 빈칸을 채웁니다.

### 2. 이상치(Outlier) 처리
대부분의 데이터 범위에서 크게 벗어난 값입니다.
*   **검출**: IQR(Interquartile Range) 방식이나 Z-Score를 사용하여 판단합니다.
*   **처리**: 이상치를 제거하거나, 상한/하한값으로 강제 조정(Clipping)합니다.

### 3. 피처 스케일링(Feature Scaling)
데이터의 범위를 일정하게 맞추는 작업입니다.
*   **정규화(Normalization/Min-Max Scaling)**: 모든 값을 0과 1 사이로 변환합니다. (데이터의 분포가 균일할 때 유리)
*   **표준화(Standardization)**: 평균을 0, 표준편차를 1로 변환합니다. (이상치가 포함되어 있을 때 더 안정적)

### 4. 범주형 인코딩(Categorical Encoding)
문자 데이터를 숫자 데이터로 변환합니다.
*   **레이블 인코딩(Label Encoding)**: 각 항목에 고유한 숫자(0, 1, 2...)를 부여합니다. (순서 의미가 있을 때 사용)
*   **원-핫 인코딩(One-Hot Encoding)**: 항목별로 새로운 열을 만들고 해당하면 1, 아니면 0을 부여합니다. (순서 의미가 없을 때 사용)

## 파이썬 코드 실습

`pandas`와 `scikit-learn`을 사용하여 지저분한 데이터를 깨끗하게 만들어 보겠습니다.

```python
import pandas as pd
import numpy as np
from sklearn.preprocessing import StandardScaler, MinMaxScaler, OneHotEncoder
from sklearn.impute import SimpleImputer

# 1. 지저분한 샘플 데이터 생성
data = {
    'Age': [25, 30, np.nan, 45, 200], # 결측치(nan)와 이상치(200) 포함
    'Salary': [5000, 6000, 5500, np.nan, 6200], # 결측치 포함
    'City': ['Seoul', 'Busan', 'Seoul', 'Incheon', 'Busan'], # 범주형 데이터
    'Target': [0, 1, 0, 1, 0]
}
df = pd.DataFrame(data)
print("--- 원본 데이터 ---\n", df, "\n")

# 2. 결측치 처리 (평균값으로 채우기)
imputer = SimpleImputer(strategy='mean')
df[['Age', 'Salary']] = imputer.fit_transform(df[['Age', 'Salary']])

# 3. 이상치 처리 (Age가 100세 이상이면 100세로 조정 - Clipping)
df['Age'] = df['Age'].clip(upper=100)

# 4. 피처 스케일링 (표준화 적용)
scaler = StandardScaler()
df[['Age', 'Salary']] = scaler.fit_transform(df[['Age', 'Salary']])

# 5. 범주형 인코딩 (원-핫 인코딩)
# pandas의 get_dummies를 사용하면 간편하게 구현 가능합니다.
df = pd.get_dummies(df, columns=['City'])

print("--- 전처리 후 데이터 ---\n", df)
```

### 실행 결과 해설

1.  **결측치 처리**: `Age`의 `NaN`은 나머지 값들의 평균으로 채워졌습니다. 이제 수학적 계산이 가능해졌습니다.
2.  **이상치 처리**: `Age`의 200세라는 비현실적인 값은 `.clip(upper=100)`을 통해 100세로 조정되었습니다. 모델이 200세라는 값에 휘둘리는 것을 방지합니다.
3.  **표준화**: `Age`와 `Salary`는 원래 단위가 완전히 달랐지만, `StandardScaler`를 거치며 평균 0, 표준편차 1인 비슷한 범위의 숫자로 변환되었습니다.
4.  **원-핫 인코딩**: `City` 열이 사라지고 `City_Seoul`, `City_Busan`, `City_Incheon`이라는 3개의 열이 생겼습니다. 각 행은 자신이 해당하는 도시에만 1을 가지고 나머지는 0을 가집니다.

## 실무 활용 사례: 고객 이탈 예측 시스템

은행에서 고객이 서비스를 해지할지 예측하는 모델을 만든다고 가정해 봅시다.

*   **문제**: 고객 데이터에는 '직업'이라는 문자열 필드와 '잔고'라는 숫자 필드가 있습니다. 일부 고객은 '소득' 정보를 입력하지 않았습니다.
*   **적용**: 
    1.  **소득**의 빈칸은 전체 고객의 중앙값으로 채워 데이터 손실을 막습니다.
    2.  **잔고** 데이터 중 억만장자 수준의 극단적 이상치는 로그 변환(Log Transform)을 통해 범위를 좁힙니다.
    3.  **직업** 필드는 원-핫 인코딩을 통해 숫자로 변환하여 모델에 입력합니다.
*   **결과**: 전처리를 거친 데이터로 학습시킨 모델은 전처리 전보다 예측 정확도가 평균 15~20% 향상되는 결과를 보입니다.

## 자주 하는 실수

**❌ 실수: 전체 데이터셋을 한 번에 스케일링하기**
*   **원인**: 학습 데이터(Train)와 테스트 데이터(Test)를 나누기 전에 전체 데이터에 `fit_transform()`을 적용하는 경우입니다.
*   **결과**: **데이터 누수(Data Leakage)**가 발생합니다. 테스트 데이터의 정보(평균, 표준편차)가 학습 과정에 미리 반영되어, 실제 서비스 시보다 성능이 과하게 높게 나오는 '낙관적 편향'이 생깁니다.
*   **해결**: 반드시 데이터를 먼저 나누고, **학습 데이터로만 `fit`**을 한 뒤, 그 기준을 테스트 데이터에 **`transform`**만 적용하세요.

## 핵심 요약

*   **데이터 전처리**는 모델 학습 전 데이터를 깨끗하고 일관된 형태로 만드는 필수 과정입니다.
*   **결측치**는 제거하거나 평균/중앙값 등으로 대체하여 처리합니다.
*   **이상치**는 IQR 등의 방법으로 검출하고, 제거하거나 특정 범위로 제한(Clipping)합니다.
*   **스케일링**은 정규화(0~1)와 표준화(평균 0, 분산 1)가 있으며, 변수 간 단위 차이를 없애줍니다.
*   **인코딩**은 문자열 데이터를 숫자로 바꾸는 과정으로, 레이블 인코딩과 원-핫 인코딩이 대표적입니다.

## 정답 및 해설

1.  **정답**: 정규화는 데이터를 0과 1 사이의 일정한 범위로 압축하는 것이고, 표준화는 데이터를 평균 0, 표준편차 1인 분포로 변환하는 것입니다. 정규화는 데이터의 분포가 균일할 때 좋고, 표준화는 이상치가 있을 때 더 강건(Robust)합니다.
2.  **정답**: 레이블 인코딩(Label Encoding) 또는 오디널 인코딩(Ordinal Encoding)입니다. 순서 정보가 중요하므로 $초졸=1, 중졸=2, \dots$ 와 같이 숫자의 크기로 순서를 표현하는 것이 유리합니다.
3.  **정답**: 학습 데이터와 테스트 데이터를 먼저 분리한 후, 학습 데이터의 통계량(평균, 표준편차 등)만을 사용하여 스케일러를 학습(`fit`)시켜야 합니다. 테스트 데이터에는 학습된 스케일러를 적용(`transform`)만 해야 합니다.
