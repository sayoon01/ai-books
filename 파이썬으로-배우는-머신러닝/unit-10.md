# 10. 모델 평가와 성능 개선

## 이번 장에서 배우는 내용

지금까지 우리는 데이터를 준비하고, 모델을 학습시키고, 예측값을 도출하는 과정을 배웠습니다. 하지만 여기서 한 가지 중요한 질문이 남습니다. **"우리가 만든 모델이 정말로 일을 잘하고 있는 걸까?"**

단순히 "예측값이 잘 맞는 것 같다"는 느낌만으로는 부족합니다. 모델의 성능을 객관적인 수치로 측정하고, 그 수치를 바탕으로 모델을 개선하는 과정이 반드시 필요합니다. 이번 장에서는 모델의 성적표라고 할 수 있는 다양한 평가 지표와, 모델의 신뢰도를 높이는 교차 검증 방법을 학습합니다.

- **평가 지표의 이해**: 정확도(Accuracy), 정밀도(Precision), 재현율(Recall), F1 스코어(F1 Score)의 개념과 차이점을 배웁니다.
- **혼동 행렬(Confusion Matrix)**: 모델이 어디서 헷갈리고 있는지 시각적으로 분석하는 방법을 배웁니다.
- **교차 검증(Cross-Validation)**: 데이터를 어떻게 나누어 검증해야 과적합(Overfitting)을 방지하고 일반화 성능을 높일 수 있는지 학습합니다.

## 실생활 비유: "너무 관대한 선생님과 너무 까다로운 선생님"

여러분이 시험 감독관이라고 가정해 봅시다. 학생이 쓴 답안지를 채점하는데, 두 명의 선생님이 서로 다른 채점 방식을 가지고 있습니다.

- **관대한 선생님 (높은 재현율)**: "조금이라도 정답에 가까우면 다 맞게 해주자!" $\rightarrow$ 정답을 하나도 놓치지 않지만, 틀린 답까지 맞다고 해줄 가능성이 큽니다.
- **까다로운 선생님 (높은 정밀도)**: "완벽하게 정답인 것만 맞게 해주자!" $\rightarrow$ 맞다고 한 답은 확실히 정답이지만, 정답인데도 조금만 부족하면 틀렸다고 처리해 많은 정답을 놓칠 수 있습니다.

우리가 원하는 것은 **정답은 정확히 맞히면서(정밀도), 정답을 놓치지 않는(재현율)** 균형 잡힌 선생님입니다. 머신러닝 모델 평가도 마찬가지입니다. 단순히 "몇 문제 맞혔나(정확도)"만 보는 것이 아니라, 모델이 어떤 성향의 실수를 하고 있는지를 파악하는 것이 핵심입니다.

## 개념 설명: 정확도만으로는 부족한 이유

가장 직관적인 지표는 **정확도(Accuracy)**입니다. 전체 예측 중 맞춘 비율을 뜻하죠. 하지만 데이터가 **불균형(Imbalanced)**할 때 정확도는 우리를 속입니다.

예를 들어, 100명 중 1명만 걸리는 희귀병 진단 모델이 있다고 합시다. 이 모델이 아무런 학습 없이 무조건 "당신은 건강합니다"라고만 답하게 설계되었다면, 100명 중 99명을 맞히므로 **정확도는 99%**가 됩니다. 수치상으로는 완벽해 보이지만, 정작 병에 걸린 1명을 찾아내지 못했으므로 이 모델은 **실전에서는 아무 쓸모가 없는 모델**입니다.

따라서 우리는 상황에 따라 다음과 같은 세분화된 지표가 필요합니다.
1. **정밀도(Precision)**: 모델이 "정답(Positive)"이라고 예측한 것들 중, 진짜 정답인 비율 (**틀린 것을 맞다고 하지 않는 능력**)
2. **재현율(Recall)**: 실제 정답인 것들 중, 모델이 "정답"이라고 맞힌 비율 (**정답을 놓치지 않는 능력**)
3. **F1 스코어(F1 Score)**: 정밀도와 재현율의 조화 평균. 두 지표가 한쪽으로 치우치지 않고 균형을 이룰 때 높은 값이 나옵니다.

## 기술 설명: 혼동 행렬과 평가 지표

이 모든 지표의 기초는 **혼동 행렬(Confusion Matrix)**입니다. 모델의 예측 결과와 실제 정답을 표로 나타낸 것입니다.

| 구분 | 실제 Positive (정답) | 실제 Negative (오답) |
| :--- | :---: | :---: |
| **예측 Positive** | **TP** (True Positive) | **FP** (False Positive) |
| **예측 Negative** | **FN** (False Negative) | **TN** (True Negative) |

- **TP**: 맞다고 예측했고, 실제로 맞음 (정답!)
- **TN**: 틀리다고 예측했고, 실제로 틀림 (정답!)
- **FP**: 맞다고 예측했지만, 실제로는 틀림 (**가짜 양성** $\rightarrow$ 정밀도 하락 요인)
- **FN**: 틀리다고 예측했지만, 실제로는 맞음 (**가짜 음성** $\rightarrow$ 재현율 하락 요인)

### 1. 지표 계산식과 의미
- $\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}$ : 전체 중 정답을 맞힌 비율
- $\text{Precision} = \frac{TP}{TP + FP}$ : 모델이 Positive라고 한 것 중 진짜 Positive인 비율
- $\text{Recall} = \frac{TP}{TP + FN}$ : 실제 Positive인 것 중 모델이 찾아낸 비율
- $\text{F1 Score} = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$ : 정밀도와 재현율의 조화 평균

**※ 왜 산술 평균이 아닌 '조화 평균'을 쓰나요?**
산술 평균은 한쪽이 매우 낮아도 다른 쪽이 높으면 평균값이 높게 나옵니다. 하지만 조화 평균은 두 값 중 하나라도 매우 낮으면 전체 값이 확 떨어집니다. 즉, 정밀도와 재현율 중 어느 하나라도 엉망이라면 F1 스코어는 낮게 나오도록 설계되어, 모델의 균형 잡힌 성능을 강제하기 위함입니다.

### 2. 교차 검증 (K-Fold Cross-Validation)
데이터를 단순히 학습용(Train)과 테스트용(Test)으로 한 번만 나누면, 우연히 테스트 데이터가 너무 쉽거나 어려울 수 있습니다. 이를 방지하기 위해 데이터를 $K$개의 덩어리(Fold)로 나누어 검증하는 방법이 **K-폴드 교차 검증**입니다.

- **작동 방식**: 
    1. 데이터를 $K$개로 나눕니다.
    2. 1번 덩어리를 검증셋으로, 나머지 $K-1$개를 학습셋으로 사용해 성능을 측정합니다.
    3. 2번 덩어리를 검증셋으로, 나머지를 학습셋으로 사용하여 반복합니다.
    4. 이 과정을 $K$번 반복하여 나온 $K$개 성능 값의 평균을 최종 성능으로 채택합니다.
- **효과**: 모든 데이터를 한 번씩 검증에 사용하므로, 특정 데이터 분할에 의한 왜곡을 줄이고 모델의 **일반화 성능**을 더 객관적으로 측정할 수 있습니다.

## 파이썬 코드 실습

불균형한 데이터셋을 생성하여 모델의 성능을 다각도로 평가하고, 교차 검증을 적용해 보겠습니다.

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.metrics import confusion_matrix, classification_report, accuracy_score
from sklearn.ensemble import RandomForestClassifier

# 1. 불균형 데이터 생성 (정상 90%, 질병 10%)
# weights=[0.9, 0.1]를 통해 클래스 비율을 조절합니다.
X, y = make_classification(n_samples=1000, n_features=10, 
                           weights=[0.9, 0.1], random_state=42)

# 데이터 분할 (stratify=y를 통해 학습/테스트 셋의 클래스 비율을 유지합니다)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, 
                                                    random_state=42, stratify=y)

# 2. 모델 학습 (랜덤 포레스트)
model = RandomForestClassifier(random_state=42)
model.fit(X_train, y_train)

# 3. 예측 및 평가
y_pred = model.predict(X_test)

print("--- [혼동 행렬] ---")
print(confusion_matrix(y_test, y_pred))

print("\n--- [상세 평가 보고서] ---")
print(classification_report(y_test, y_pred))

# 4. 교차 검증 수행 (5-Fold)
cv_scores = cross_val_score(model, X, y, cv=5)
print(f"\n--- [5-Fold 교차 검증 결과] ---")
print(f"각 폴드 정확도: {cv_scores}")
print(f"평균 정확도: {np.mean(cv_scores):.4f}")
```

---

## 실행 결과 해설

### 1. 혼동 행렬 해석
출력된 혼동 행렬이 다음과 같다고 가정해 봅시다.
`[[260, 10], [2, 28]]`
- **TN=260, FP=10**: 건강한 사람 270명 중 10명을 환자로 오진했습니다. (정밀도 하락)
- **FN=2, TP=28**: 환자 30명 중 2명을 놓치고 28명을 찾아냈습니다. (재현율 하락)

### 2. 상세 보고서 해석
- **Precision (정밀도)**: 모델이 "환자"라고 예측한 사람 중 실제 환자의 비율입니다. FP(오진)가 많을수록 낮아집니다.
- **Recall (재현율)**: 실제 환자들 중 모델이 정확히 "환자"라고 찾아낸 비율입니다. FN(놓친 환자)이 많을수록 낮아집니다.
- **F1-Score**: 정밀도와 재현율의 조화 평균입니다. 두 지표가 모두 높아야만 이 값이 높게 나옵니다.

### 3. 교차 검증 결과
단일 테스트 셋의 결과가 아니라, 데이터를 5번 다르게 나누어 테스트한 평균값이 출력됩니다. 각 폴드의 정확도가 서로 비슷하고 평균값이 안정적이라면, 모델이 특정 데이터에만 최적화되지 않고 새로운 데이터에도 잘 작동하는 **일반화 성능**을 갖췄다고 판단할 수 있습니다.

## 실무 활용 사례: 정밀도 vs 재현율, 무엇을 선택할까?

실무에서는 비즈니스 목적에 따라 중요하게 생각하는 지표가 다릅니다. 이를 **정밀도-재현율 트레이드오프(Trade-off)**라고 하며, 하나를 높이면 다른 하나가 낮아지는 경향이 있습니다.

- **재현율(Recall)이 최우선인 경우: 암 진단, 화재 경보, 결함 검출**
    - 실제 환자를 건강하다고 판정(FN)하는 것은 생명과 직결되는 치명적인 실수입니다. 조금 과하게 진단하여 정밀도가 낮아지더라도(FP 증가), 일단 모든 환자를 찾아내는 것이 훨씬 중요합니다.
- **정밀도(Precision)가 최우선인 경우: 스팸 메일 분류, 유죄 판결, 추천 시스템**
    - 중요한 업무 메일을 스팸으로 분류(FP)하여 삭제해버리면 큰 업무 손실이 발생합니다. 혹은 무고한 사람을 유죄로 판결하는 것은 용납될 수 없습니다. 따라서 확실한 경우에만 Positive라고 판정하는 것이 중요합니다.

## 자주 하는 실수

**"정확도가 95%니까 아주 훌륭한 모델이야!"**
$\rightarrow$ **가장 위험한 생각입니다.** 데이터의 클래스 비율을 먼저 확인하세요. 95%가 '정상'인 데이터라면, 아무런 학습 없이 "모두 정상"이라고만 답해도 정확도는 95%가 나옵니다. 이를 **정확도의 역설(Accuracy Paradox)**이라고 합니다. 항상 `classification_report`를 통해 클래스별 정밀도와 재현율을 확인하는 습관을 들여야 합니다.

## 핵심 요약

- **정확도(Accuracy)**는 전체 중 맞춘 비율이지만, 데이터가 불균형할 때 신뢰하기 어렵다.
- **정밀도(Precision)**는 모델이 '정답'이라 한 것 중 실제 정답의 비율이다. (FP 최소화 $\rightarrow$ "신중한 예측")
- **재현율(Recall)**은 실제 정답 중 모델이 맞춘 비율이다. (FN 최소화 $\rightarrow$ "꼼꼼한 예측")
- **F1 스코어**는 정밀도와 재현율의 조화 평균으로, 두 지표의 균형을 나타낸다.
- **교차 검증(Cross-Validation)**은 데이터를 여러 번 나누어 검증함으로써 모델의 일반화 성능을 측정하고 과적합을 방지하는 방법이다.

## 정답 및 해설

1. **정답**: 재현율 0.8(80%), 정밀도 0.5(50%)
   - 재현율 = $\frac{\text{실제 환자 중 맞춘 환자}}{\text{전체 실제 환자}} = \frac{8}{10} = 0.8$
   - 정밀도 = $\frac{\text{예측 환자 중 실제 환자}}{\text{전체 예측 환자}} = \frac{5}{10} = 0.5$
2. **정답**: 모델이 모든 데이터를 '정상'이라고만 예측해도 정확도가 99%가 나옵니다. 따라서 실제로 '불량'을 찾아내는 능력이 전혀 없는 모델임에도 불구하고 성능이 매우 좋다고 착각하는 '정확도의 역설'이 발생합니다.
3. **정답**: $K$를 높이면 더 많은 데이터를 학습에 사용할 수 있어 모델의 성능을 더 정밀하게 측정할 수 있습니다. 단순히 한 번 나누는 것보다 데이터의 다양한 조합을 검증셋으로 사용하므로, 특정 데이터 셋에만 우연히 잘 맞는 '운 좋은 결과'를 배제하고 객관적인 일반화 성능을 측정할 수 있기 때문입니다.
