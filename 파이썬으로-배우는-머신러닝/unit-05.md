- **결측치 처리**: 비어 있는 데이터(NaN)를 어떻게 채우거나 제거할 것인가?
- **이상치 처리**: 너무 튀는 값(Outlier)을 어떻게 식별하고 처리할 것인가?

## 실생활 비유: 요리 전 '재료 손질'

여러분들이 최고의 셰프가 되어 맛있는 요리를 만든다고 가정해 봅시다. 아무리 좋은 레시피(머신러닝 알고리즘)가 있고 최신식 오븐(고성능 컴퓨터)이 있어도, 재료가 엉망이라면 결과물은 좋을 수 없습니다.

- 흙이 묻은 당근을 그대로 넣지 않고 씻어내는 것 $\rightarrow$ **결측치/이상치 제거**
- 너무 큰 고기 덩어리를 일정한 크기로 써는 것 $\rightarrow$ **스케일링**
- 외국어 레시피를 내가 이해할 수 있는 언어로 번역하는 것 $\rightarrow$ **인코딩**

이처럼 재료를 다듬는 '손질' 과정이 없으면 요리를 망치듯, 데이터 전처리가 제대로 되지 않은 모델은 잘못된 예측을 내놓습니다. 이를 데이터 과학에서는 **"Garbage In, Garbage Out(쓰레기가 들어가면 쓰레기가 나온다)"**라고 표현합니다.

## 개념 및 기술 설명

### 1. 결측치 (Missing Value) 처리
결측치는 데이터 수집 과정에서 누락되어 값이 비어 있는 상태(`NaN`, `Null`)를 말합니다.

- **직관**: 설문조사에서 응답자가 나이 항목을 적지 않고 제출한 상황입니다.
- **기술적 처리 방법**:
    - **제거 (Deletion)**: 결측치가 너무 많거나, 해당 행이 중요하지 않을 때 삭제합니다.
    - **대체 (Imputation)**: 평균값, 중앙값, 최빈값 등으로 빈칸을 채웁니다.

### 2. 이상치 (Outlier) 처리
이상치는 대부분의 데이터 분포에서 크게 벗어나 아주 작거나 아주 큰 값을 말합니다.

- **직관**: 우리 반 학생들의 평균 키가 170cm인데, 갑자기 230cm인 학생이 데이터에 포함된 상황입니다. 이는 측정 오류일 수도 있고, 아주 희귀한 사례일 수도 있습니다.
- **기술적 처리 방법**:
    - **IQR(Interquartile Range) 방식**: 데이터의 상위 25%와 하위 25% 범위를 이용해 경계선을 정하고 그 밖의 값을 이상치로 간주합니다.
    - **제거 또는 대체**: 이상치를 삭제하거나, 상한/하한값으로 조정(Capping)합니다.

### 3. 특성 스케일링 (Feature Scaling)
머신러닝 알고리즘은 숫자의 '크기'에 민감합니다. 예를 들어 '연봉(천만 단위)'과 '나이(십 단위)'가 함께 있다면, 모델은 연봉이 훨씬 중요한 변수라고 착각할 수 있습니다.

- **정규화 (Normalization/Min-Max Scaling)**: 모든 값을 0과 1 사이로 변환합니다.
    - $\text{결과} = \frac{x - \text{min}}{\text{max} - \text{min}}$
- **표준화 (Standardization)**: 평균을 0, 표준편차를 1로 변환하여 종 모양의 정규분포 형태로 만듭니다.
    - $\text{결과} = \frac{x - \text{평균}}{\text{표준편차}}$

### 4. 범주형 데이터 인코딩 (Encoding)
컴퓨터는 '서울', '부산' 같은 문자열을 계산할 수 없습니다. 따라서 이를 숫자로 바꿔줘야 합니다.

- **레이블 인코딩 (Label Encoding)**: 각 범주에 고유한 숫자를 부여합니다. (예: 서울 $\rightarrow$ 0, 부산 $\rightarrow$ 1)
    - *주의*: 모델이 0 < 1이라는 크기 관계를 학습하여 잘못된 판단을 내릴 수 있습니다.
- **원-핫 인코딩 (One-Hot Encoding)**: 해당 범주인지 아닌지를 0과 1로 표시하는 새로운 열을 만듭니다.
    - *예*: '도시' 열 $\rightarrow$ '도시_서울'(0 or 1), '도시_부산'(0 or 1)

## 파이썬 코드 실습

다음은 결측치, 이상치, 스케일링, 인코딩을 한 번에 처리하는 통합 실습 코드입니다.

```python
import pandas as pd
import numpy as np
from sklearn.preprocessing import StandardScaler, MinMaxScaler, LabelEncoder

# 1. 가상의 데이터 생성
data = {
    'Age': [25, 30, 35, np.nan, 40, 200], # 200은 이상치, nan은 결측치
    'Salary': [5000, 6000, np.nan, 8000, 7000, 6500],
    'City': ['Seoul', 'Busan', 'Seoul', 'Incheon', 'Busan', 'Seoul'],
    'Purchased': ['Yes', 'No', 'Yes', 'No', 'Yes', 'No']
}
df = pd.DataFrame(data)
print("--- 원본 데이터 ---\n", df, "\n")

# 2. 결측치 처리: 평균값으로 채우기
df['Age'] = df['Age'].fillna(df['Age'].median()) # 나이는 중앙값으로
df['Salary'] = df['Salary'].fillna(df['Salary'].mean()) # 급여는 평균값으로
print("--- 결측치 처리 후 ---\n", df, "\n")

# 3. 이상치 처리: Age가 100세 이상인 데이터를 60세로 조정 (Capping)
df.loc[df['Age'] > 100, 'Age'] = 60
print("--- 이상치 처리 후 ---\n", df, "\n")

# 4. 인코딩
# 범주형 변수 'City' -> 원-핫 인코딩
df = pd.get_dummies(df, columns=['City'])
# 타겟 변수 'Purchased' -> 레이블 인코딩
le = LabelEncoder()
df['Purchased'] = le.fit_transform(df['Purchased'])
print("--- 인코딩 후 ---\n", df, "\n")

# 5. 스케일링 (표준화)
scaler = StandardScaler()
df[['Age', 'Salary']] = scaler.fit_transform(df[['Age', 'Salary']])
print("--- 최종 전처리 완료 (표준화 적용) ---\n", df)
```

### 실행 결과 해설

1. **결측치 처리**: `np.nan`이었던 값들이 각각 나이의 중앙값과 급여의 평균값으로 채워졌습니다. 데이터의 손실 없이 학습 데이터를 유지할 수 있습니다.
2. **이상치 처리**: 나이가 `200`이었던 비정상적인 값이 `60`으로 조정되었습니다. 이 과정이 없었다면 모델은 "나이가 많을수록 급여가 급격히 변한다"는 잘못된 패턴을 학습했을 것입니다.
3. **인코딩**: `City` 열이 `City_Busan`, `City_Incheon`, `City_Seoul`이라는 세 개의 열로 분리되었고, 값은 0과 1로 바뀌었습니다. 이제 모델이 계산 가능한 형태가 되었습니다.
4. **스케일링**: `Age`와 `Salary`의 수치 범위가 매우 달랐지만, 표준화 이후 두 변수 모두 평균 0, 표준편차 1의 비슷한 범위 내로 들어왔습니다.

## 실무 활용 사례: 고객 이탈 예측 시스템

통신사에서 고객이 서비스를 해지할지 예측하는 모델을 만든다고 가정해 봅시다.
- **상황**: 고객 데이터에 '마지막 접속일'이 비어 있거나(결측치), 한 달에 데이터를 100GB 사용한 헤비 유저(이상치)가 섞여 있습니다. 또한 '가입 경로(온라인/오프라인)' 같은 텍스트 데이터가 존재합니다.
- **적용**: 
    1. 비어 있는 접속일은 가장 최근 날짜의 평균으로 채웁니다.
    2. 데이터 사용량이 너무 높은 상위 1%는 별도의 '헤비 유저' 그룹으로 분리하거나 상한선을 둡니다.
    3. 가입 경로를 원-핫 인코딩하여 모델에 입력합니다.
- **결과**: 전처리를 거친 데이터로 학습시킨 모델은 전처리 전보다 예측 정확도(Accuracy)가 약 10~20% 향상되는 경향을 보입니다.

## 자주 하는 실수

**❌ 스케일링을 데이터 분할(Split) 전에 수행하는 경우**
- **문제**: 전체 데이터에 대해 스케일링을 먼저 하고 훈련 세트와 테스트 세트로 나누면, 훈련 세트가 테스트 세트의 정보(평균, 표준편차 등)를 미리 알게 되는 **'데이터 누수(Data Leakage)'** 현상이 발생합니다.
- **해결**: 반드시 `train_test_split`으로 데이터를 먼저 나눈 뒤, 훈련 세트의 기준(scaler.fit)으로 테스트 세트를 변환(scaler.transform)해야 합니다.

**❌ 모든 범주형 변수에 레이블 인코딩을 사용하는 경우**
- **문제**: '서울(0), 부산(1), 제주(2)'라고 인코딩하면, 모델은 "제주가 서울보다 2배 더 크다"거나 "부산은 서울과 제주의 중간이다"라고 잘못 해석할 수 있습니다.
- **해결**: 순서 의미가 없는 명목형 데이터에는 반드시 **원-핫 인코딩**을 사용하세요.

## 핵심 요약
- **결측치**: 비어 있는 값 $\rightarrow$ 삭제하거나 평균/중앙값 등으로 대체.
- **이상치**: 너무 튀는 값 $\rightarrow$ IQR 등으로 탐지 후 제거하거나 조정.
- **스케일링**: 단위 맞추기 $\rightarrow$ 정규화(0~1) 또는 표준화(평균 0, 표준편차 1).
- **인코딩**: 문자를 숫자로 $\rightarrow$ 레이블 인코딩(순서 있음) 또는 원-핫 인코딩(순서 없음).
