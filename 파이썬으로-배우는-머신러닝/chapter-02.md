# 챕터 2: 데이터 전처리

# 챕터 2: 데이터 전처리 — 모델의 성능을 결정짓는 '데이터 정제'의 마법

머신러닝 프로젝트를 시작하는 많은 입문자가 가장 먼저 하는 실수는 바로 '어떤 알고리즘을 쓸까?'를 고민하는 것입니다. 하지만 숙련된 데이터 사이언티스트들은 입을 모아 말합니다. **"모델의 성능은 알고리즘이 아니라 데이터의 품질이 결정한다"**라고 말이죠.

머신러닝 세계에는 **'GIGO(Garbage In, Garbage Out)'**라는 유명한 원칙이 있습니다. '쓰레기가 들어가면 쓰레기가 나온다'는 뜻입니다. 아무리 최신 기법의 고성능 모델을 사용하더라도, 입력되는 데이터가 엉망이라면 결과 역시 신뢰할 수 없는 쓰레기에 불과합니다. 따라서 우리는 모델을 학습시키기 전, 데이터를 깨끗하고 일관된 형태로 다듬는 **'데이터 전처리(Data Preprocessing)'** 과정을 반드시 거쳐야 합니다.

---

## 1. 빈틈과 튀는 값 잡기: 결측치 및 이상치 처리

현실 세계에서 수집된 데이터는 결코 완벽하지 않습니다. 설문 조사 응답자가 특정 항목을 누락했을 수도 있고, 센서 오작동으로 말도 안 되는 수치가 기록될 수도 있습니다.

### 결측치(Missing Value) 처리
결측치는 데이터셋에 값이 비어 있는 상태(NaN, Null)를 말합니다. 이를 방치하면 대부분의 머신러닝 알고리즘은 오류를 일으키거나 잘못된 학습을 하게 됩니다. 결측치를 처리하는 전략은 크게 두 가지입니다.

*   **삭제(Deletion):** 결측치가 포함된 행이나 열을 통째로 지우는 방법입니다. 데이터 양이 충분하고 결측치 비율이 매우 낮을 때 유용하지만, 너무 많이 지우면 중요한 정보까지 잃게 됩니다.
*   **대체(Imputation):** 빈 값을 특정 값으로 채워 넣는 방법입니다. 수치형 데이터라면 **평균(Mean)**이나 **중앙값(Median)**으로, 범주형 데이터라면 **최빈값(Most Frequent)**으로 채우는 것이 일반적입니다.

### 이상치(Outlier) 처리
이상치는 다른 데이터들과 비교했을 때 극단적으로 크거나 작은 값을 말합니다. 예를 들어, 일반적인 성인의 키 데이터셋에 '300cm'라는 값이 들어있다면 이는 명백한 이상치입니다. 이상치는 모델이 데이터의 일반적인 패턴을 학습하는 것을 방해하고, 예측 결과에 심각한 왜곡을 줍니다. 이를 해결하기 위해 상하한선을 정해 값을 자르거나(Clipping), 이상치로 판단되는 데이터를 제거하는 과정이 필요합니다.

## 2. 데이터의 체급 맞추기: 특성 스케일링(Feature Scaling)

머신러닝 모델은 기본적으로 '숫자'를 계산합니다. 그런데 서로 다른 특성(Feature)들이 가진 숫자의 범위가 너무 다르면 모델은 혼란에 빠집니다.

예를 들어, **[나이(0~100세)]**와 **[연봉(0~수억 원)]**이라는 두 가지 데이터를 함께 사용한다고 가정해 봅시다. 모델 입장에서 '연봉'의 수치는 '나이'보다 훨씬 큽니다. 그러면 모델은 나이의 변화보다 연봉의 변화가 훨씬 중요하다고 착각하게 됩니다. 이를 방지하기 위해 데이터의 범위를 일정하게 맞춰주는 것이 **특성 스케일링**입니다.

*   **정규화(Normalization):** 모든 값을 0과 1 사이의 값으로 변환하는 방법입니다. (Min-Max Scaling) 데이터의 분포가 균일할 때 유리합니다.
*   **표준화(Standardization):** 데이터의 평균을 0, 표준편차를 1로 변환하여 데이터의 척도를 통일하는 방법입니다. (Z-Score Scaling) 이상치의 영향력을 줄이고 싶을 때 효과적입니다.

## 3. 글자를 숫자로: 범주형 데이터의 수치화

컴퓨터는 '서울', '부산', '제주' 같은 텍스트(범주형 데이터)를 직접 이해할 수 없습니다. 따라서 이를 숫자로 바꾸어주어야 합니다.

### 레이블 인코딩(Label Encoding)
각 범주에 고유한 정수를 부여하는 방식입니다. (예: 서울 $\rightarrow$ 0, 부산 $\rightarrow$ 1, 제주 $\rightarrow$ 2) 
하지만 여기에는 치명적인 약점이 있습니다. 모델이 **'제주(2)가 서울(0)보다 더 크다'** 혹은 **'값이 높으니 더 중요하다'**라고 잘못 해석할 수 있다는 점입니다. 따라서 순서 의미가 있는 데이터(예: 직급-사원, 대리, 과장)에만 사용해야 합니다.

### 원-핫 인코딩(One-Hot Encoding)
순서 의미가 없는 데이터에 사용하는 방식입니다. 각 범주를 새로운 열(Column)로 만들고, 해당되는 곳에만 1을, 나머지는 0을 표시합니다.
*   **서울:** [1, 0, 0]
*   **부산:** [0, 1, 0]
*   **제주:** [0, 0, 1]
이렇게 하면 각 지역이 서로 독립적인 상태가 되어, 모델이 잘못된 서열 관계를 학습하는 것을 방지할 수 있습니다.

## 💡 실전 예시: 중고차 가격 예측 데이터 전처리

우리가 **'중고차 가격'**을 예측하는 모델을 만든다고 가정해 봅시다. 수집된 데이터가 다음과 같습니다.

| 차량 모델 | 주행거리(km) | 연식 | 사고유무 | 가격(만원) |
| :--- | :--- | :--- | :--- | :--- |
| 아반떼 | 50,000 | 2018 | 무 | 1,200 |
| 소나타 | NaN | 2015 | 유 | 800 |
| 그랜저 | 1,000,000 | 2020 | 무 | 2,500 |
| K5 | 30,000 | 2017 | 무 | 1,100 |

이 데이터를 그대로 모델에 넣으면 어떻게 될까요? 성능이 매우 낮을 것입니다. 이제 전처리를 적용해 보겠습니다.

1.  **결측치 처리:** 소나타의 '주행거리'가 비어 있습니다. 전체 차량의 평균 주행거리로 이 값을 채웁니다.
2.  **이상치 처리:** 그랜저의 주행거리 '1,000,000km'는 일반적인 중고차 범위에서 너무 튑니다. 이를 제거하거나 상한값으로 조정합니다.
3.  **특성 스케일링:** 주행거리(만 단위)와 연식(천 단위)의 숫자 범위가 다릅니다. 두 값을 모두 0~1 사이로 **정규화**하여 체급을 맞춥니다.
4.  **범주형 데이터 수치화:** '사고유무'는 '유(1), 무(0)'로 **레이블 인코딩**하고, '차량 모델'은 **원-핫 인코딩**을 통해 각각의 열로 분리합니다.

## 4. 마지막 관문: 데이터셋 분리 (Train vs Test)

전처리가 끝났다면 이제 모델에게 공부를 시킬 차례입니다. 그런데 여기서 가장 중요한 원칙이 있습니다. **"시험 문제를 미리 알려주지 마라"**는 것입니다.

우리가 가진 데이터를 모두 학습에 사용하면, 모델은 데이터를 단순히 '암기'해버릴 위험이 있습니다. 이를 **과적합(Overfitting)**이라고 합니다. 암기만 잘하는 모델은 학습 데이터에서는 100점을 맞지만, 처음 보는 실제 데이터에서는 엉망인 결과를 내놓습니다.

이를 방지하기 위해 데이터를 두 그룹으로 나눕니다.
*   **학습 세트(Training set):** 모델이 패턴을 학습하는 데 사용하는 교과서입니다. (보통 전체의 70~80%)
*   **테스트 세트(Test set):** 학습이 끝난 모델의 실력을 평가하는 시험지입니다. 모델이 한 번도 본 적 없는 데이터여야 하며, 이를 통해 모델의 **일반화 성능**을 측정합니다.

이제 데이터는 깨끗해졌고, 체급도 맞췄으며, 시험지까지 준비되었습니다. 다음 챕터에서는 이렇게 정제된 데이터를 가지고 실제로 예측 모델을 만들어 보겠습니다.
