# 5장. 데이터 전처리: 머신러닝을 위한 데이터 다듬기

머신러닝 모델의 성능은 어떤 알고리즘을 사용하느냐보다 **'어떤 데이터를 입력하느냐'**에 더 큰 영향을 받습니다. 아무리 뛰어난 요리사(알고리즘)라도 재료(데이터)가 썩어 있거나 손질되지 않았다면 훌륭한 요리를 만들 수 없는 것과 같습니다. 이번 장에서는 원시 데이터(Raw Data)를 머신러닝 모델이 학습하기 좋은 형태로 가공하는 '데이터 전처리' 과정을 배워보겠습니다.

## 5.1 결측치 처리 (Handling Missing Values)

### 🧩 비유로 이해하기: 구멍 난 퍼즐 맞추기
우리가 1,000피스짜리 퍼즐을 맞추고 있는데, 몇몇 조각이 사라졌다고 가정해 봅시다. 전체 그림을 완성하려면 어떻게 해야 할까요? 방법은 크게 두 가지입니다. 사라진 조각이 너무 적다면 그냥 무시하고 나머지 그림을 맞추거나, 주변 조각들의 색깔과 패턴을 보고 사라진 조각이 어떤 모양이었을지 추측해서 그려 넣는 것입니다.

### 💡 직관적으로 이해하기
데이터셋에서 값이 비어 있는 상태를 **결측치(Missing Value)**라고 합니다. 설문조사에서 응답자가 특정 문항에 답을 하지 않았거나, 센서 오작동으로 데이터가 기록되지 않은 경우 발생합니다. 머신러닝 모델은 기본적으로 '빈칸'을 처리할 수 없습니다. 빈칸이 있으면 계산 과정에서 오류가 발생하거나, 모델이 잘못된 판단을 내릴 가능성이 큽니다.

### 🛠 기술적 설명
결측치는 보통 `NaN`(Not a Number)으로 표시됩니다. 이를 처리하는 가장 대표적인 방법은 **삭제(Deletion)**와 **대체(Imputation)**입니다.

1.  **삭제**: 결측치가 포함된 행(Row)나 열(Column)을 통째로 제거합니다. 데이터 양이 충분하고 결측치 비중이 매우 낮을 때 사용합니다.
2.  **대체**: 특정 값으로 빈칸을 채웁니다.
    *   **평균값(Mean)**: 수치형 데이터에서 가장 일반적인 방법입니다.
    *   **중앙값(Median)**: 이상치가 많아 평균이 왜곡될 때 사용합니다.
    *   **최빈값(Mode)**: 범주형(문자열) 데이터에서 가장 자주 등장하는 값으로 채웁니다.

#### 💻 실습: 결측치 찾아내고 채우기

```python
import pandas as pd
import numpy as np

# 1. 샘플 데이터 생성 (결측치가 포함된 데이터)
data = {
    'Name': ['Alice', 'Bob', 'Charlie', 'David', 'Eve'],
    'Age': [25, np.nan, 30, np.nan, 22],
    'Score': [85, 90, np.nan, 70, 95],
    'City': ['Seoul', 'Busan', 'Seoul', np.nan, 'Incheon']
}
df = pd.DataFrame(data)
print("--- 원본 데이터 ---")
print(df)

# 2. 결측치 확인
print("\n--- 결측치 개수 확인 ---")
print(df.isnull().sum())

# 3. 결측치 처리
# Age: 평균값으로 대체
df['Age'] = df['Age'].fillna(df['Age'].mean())

# Score: 중앙값으로 대체
df['Score'] = df['Score'].fillna(df['Score'].median())

# City: 최빈값으로 대체
most_freq_city = df['City'].mode()[0]
df['City'] = df['City'].fillna(most_freq_city)

print("\n--- 전처리 후 데이터 ---")
print(df)
```

**실행 결과 해석:**
- `isnull().sum()`을 통해 각 컬럼별로 몇 개의 데이터가 비어 있는지 확인했습니다.
- `Age`는 `(25+30+22)/3`의 평균값으로 채워졌습니다.
- `Score`는 정렬했을 때 가운데 값인 중앙값으로 채워졌습니다.
- `City`는 가장 많이 등장한 'Seoul'로 채워졌습니다.

> **⚠️ 초보자가 자주 하는 실수**
> **실수:** 모든 결측치를 무조건 평균값으로 채우는 경우.
> **해결:** 데이터의 분포를 먼저 확인하세요. 예를 들어, 소득 데이터처럼 극단적으로 높은 값이 섞여 있는 경우 평균값은 왜곡될 수 있으므로 **중앙값(Median)**을 사용하는 것이 훨씬 안전합니다.

## 5.2 이상치 처리 (Handling Outliers)

### 🐘 비유로 이해하기: 유치원생들 사이에 낀 거인
유치원 아이들의 평균 키를 측정하는데, 갑자기 2m가 넘는 거인이 한 명 들어왔다고 생각해보세요. 이 거인 한 명 때문에 유치원 아이들의 평균 키가 갑자기 1m 50cm로 껑충 뜁니다. 하지만 이 결과가 유치원 아이들의 실제 키 수준을 대표한다고 말할 수 있을까요? 아니요, 거인은 '특이한 케이스'일 뿐입니다.

### 💡 직관적으로 이해하기
**이상치(Outlier)**란 다른 데이터들과 비교했을 때 극단적으로 크거나 작은 값을 말합니다. 이상치가 포함된 데이터를 그대로 학습시키면 머신러닝 모델은 이 극단적인 값에 과하게 반응하여, 일반적인 데이터들에 대한 예측 성능이 떨어지는 현상이 발생합니다.

### 🛠 기술적 설명
이상치를 판별하는 가장 대표적인 방법은 **IQR(Interquartile Range)** 방식입니다.

- **Q1 (1사분위수)**: 하위 25% 지점의 값
- **Q3 (3사분위수)**: 상위 25% 지점의 값
- **IQR**: $Q3 - Q1$
- **이상치 범위**: 
    - 하한선: $Q1 - 1.5 \times IQR$
    - 상한선: $Q3 + 1.5 \times IQR$

`[그림 5-1: IQR을 이용한 이상치 판별 범위 - 박스 플롯(Box Plot)을 통해 Q1, Q3, IQR 및 상하한선이 표시되고, 범위를 벗어난 점들이 이상치로 표시된 모습]`

- 이 범위를 벗어나는 값은 이상치로 판단하여 제거하거나 상/하한값으로 조정합니다.

#### 💻 실습: IQR을 이용한 이상치 제거

```python
import pandas as pd
import numpy as np

# 1. 이상치가 포함된 데이터 생성 (대부분 20~30대인데 한 명만 200살)
data = {'Age': [22, 25, 28, 24, 21, 29, 200, 23, 26, 27]}
df = pd.DataFrame(data)

# 2. IQR 계산
Q1 = df['Age'].quantile(0.25)
Q3 = df['Age'].quantile(0.75)
IQR = Q3 - Q1

lower_bound = Q1 - 1.5 * IQR
upper_bound = Q3 + 1.5 * IQR

print(f"IQR: {IQR}, 하한선: {lower_bound}, 상한선: {upper_bound}")

# 3. 이상치 필터링
df_clean = df[(df['Age'] >= lower_bound) & (df['Age'] <= upper_bound)]

print("\n--- 제거 전 데이터 ---")
print(df)
print("\n--- 이상치 제거 후 데이터 ---")
print(df_clean)
```

**실행 결과 해석:**
- `Age` 데이터 중 `200`이라는 값은 상한선(`upper_bound`)을 훨씬 초과합니다.
- 필터링 조건을 통해 `200`이 제거된 `df_clean` 데이터셋이 생성되었습니다. 이제 모델은 더 이상 '200살'이라는 비현실적인 데이터에 휘둘리지 않습니다.

> **⚠️ 초보자가 자주 하는 실수**
> **실수:** 이상치가 발견되면 무조건 데이터를 삭제하는 경우.
> **해결:** 데이터 양이 적을 때 무분별하게 삭제하면 중요한 정보를 잃을 수 있습니다. 이럴 때는 이상치를 삭제하는 대신, 상한선이나 하한선 값으로 강제로 맞추는 **'윈저라이징(Winsorizing)'** 또는 **'Capping'** 기법을 고려해 보세요.

## 5.3 데이터 스케일링: 정규화와 표준화 (Feature Scaling)

### ⚖️ 비유로 이해하기: 킬로그램(kg)과 밀리미터(mm)의 대결
당신이 건강 상태를 판단하는 AI를 만드는데, 입력값으로 '몸무게(kg)'와 '키(mm)'를 넣는다고 가정해 봅시다. 
- 몸무게: 70kg
- 키: 1750mm
숫자만 보면 1750이 70보다 훨씬 큽니다. AI는 단순하게 "숫자가 큰 키(mm)가 몸무게보다 훨씬 더 중요한 정보구나!"라고 오해할 수 있습니다. 단위가 다르기 때문에 발생하는 착시 현상입니다.

### 💡 직관적으로 이해하기
머신러닝 알고리즘(특히 거리 기반 알고리즘인 KNN, SVM이나 경사하강법을 쓰는 딥러닝)은 숫자의 절대적인 크기에 민감합니다. 따라서 서로 다른 단위를 가진 특성(Feature)들을 **동일한 범위나 기준**으로 맞춰주는 작업이 필요합니다. 이를 **스케일링(Scaling)**이라고 합니다.

### 🛠 기술적 설명
가장 많이 쓰이는 두 가지 방법이 **정규화(Normalization)**와 **표준화(Standardization)**입니다.

| 구분 | 정규화 (Min-Max Scaling) | 표준화 (Standard Scaling) |
| :--- | :--- | :--- |
| **방식** | 모든 값을 0과 1 사이로 압축 | 평균을 0, 표준편차를 1로 변환 |
| **공식** | $\frac{x - \min}{\max - \min}$ | $\frac{x - \text{mean}}{\text{std}}$ |
| **특징** | 데이터의 최소/최대값이 명확할 때 유리 | 이상치가 존재해도 상대적으로 덜 민감함 |
| **결과** | 항상 $[0, 1]$ 범위 내 존재 | 정해진 범위는 없으나 0 근처에 밀집 |

#### 💻 실습: 정규화와 표준화 적용하기

```python
from sklearn.preprocessing import MinMaxScaler, StandardScaler
import pandas as pd

# 1. 서로 다른 스케일을 가진 데이터 생성
data = {
    'Weight': [50, 80, 60, 90, 70], # kg 단위
    'Height': [1500, 1800, 1600, 1900, 1700] # mm 단위
}
df = pd.DataFrame(data)
print("--- 원본 데이터 ---")
print(df)

# 2. 정규화 (Min-Max Scaling)
min_max_scaler = MinMaxScaler()
df_normalized = pd.DataFrame(min_max_scaler.fit_transform(df), columns=df.columns)

# 3. 표준화 (Standard Scaling)
std_scaler = StandardScaler()
df_standardized = pd.DataFrame(std_scaler.fit_transform(df), columns=df.columns)

print("\n--- 정규화 결과 (0~1 사이) ---")
print(df_normalized)
print("\n--- 표준화 결과 (평균 0, 표준편차 1) ---")
print(df_standardized)
```

**실행 결과 해석:**
- **정규화 결과**: 모든 값이 0.0에서 1.0 사이로 변환되었습니다. 가장 작은 값은 0, 가장 큰 값은 1이 됩니다.
- **표준화 결과**: 값들이 0을 중심으로 분포합니다. 음수 값이 나타나는 이유는 평균보다 작은 값들이기 때문입니다.

> **⚠️ 초보자가 자주 하는 실수**
> **실수:** 전체 데이터셋에 대해 스케일링을 먼저 수행한 후, 데이터를 훈련 세트(Train set)와 테스트 세트(Test set)로 나누는 경우.
> **해결:** 이는 **데이터 누수(Data Leakage)**라는 심각한 문제를 일으킵니다. 반드시 데이터를 먼저 나눈 뒤, **훈련 세트로만 스케일러를 학습(`fit`)**시키고, 그 기준을 테스트 세트에 **적용(`transform`)**만 해야 합니다. 테스트 데이터의 정보가 훈련 과정에 미리 반영되는 것을 막기 위함입니다.

## 5.4 범주형 데이터 인코딩 (Encoding)

### 🗣️ 비유로 이해하기: 컴퓨터를 위한 통역사
컴퓨터는 숫자밖에 모르는 '수학 천재'이지만, '빨강', '파랑', '초록' 같은 단어는 전혀 이해하지 못합니다. 우리가 컴퓨터에게 색상을 알려주려면 "빨강은 1번, 파랑은 2번, 초록은 3번이야"라고 숫자로 통역해줘야 합니다.

### 💡 직관적으로 이해하기
머신러닝 모델의 입력값은 반드시 숫자여야 합니다. 따라서 '도시 이름', '성별', '혈액형' 같은 문자열 데이터(범주형 데이터)를 숫자로 바꾸는 과정이 필요합니다. 하지만 단순히 숫자로 바꾸기만 하면 문제가 생길 수 있습니다. 예를 들어 '서울=1, 부산=2, 대구=3'으로 바꾸면, 모델은 '대구(3)가 서울(1)보다 3배 더 크다'거나 '서울과 부산의 평균은 1.5다'라는 식의 잘못된 수학적 해석을 할 수 있습니다.

### 🛠 기술적 설명
이를 해결하기 위해 두 가지 인코딩 방식을 사용합니다.

1.  **레이블 인코딩 (Label Encoding)**:
    - 각 범주를 단순한 정수로 변환합니다. (예: 빨강 $\rightarrow$ 0, 파랑 $\rightarrow$ 1, 초록 $\rightarrow$ 2)
    - **주의**: 순서나 등급의 의미가 없는 데이터에 사용하면 모델이 잘못된 순위 정보를 학습할 수 있습니다. (서열이 있는 데이터-예: 직급-에 적합)
2.  **원-핫 인코딩 (One-Hot Encoding)**:
    - 각 범주를 새로운 열(Column)로 만들고, 해당하면 1, 아니면 0으로 표시합니다.
    - **특징**: 범주 간의 독립성을 유지하므로 대부분의 머신러닝 모델에서 권장되는 방식입니다.

`[그림 5-2: 원-핫 인코딩의 변환 과정 - 'City'라는 하나의 열이 'City_Seoul', 'City_Busan', 'City_Daegu'라는 3개의 열로 확장되며, 각 행마다 해당하는 도시 열에만 1이 표시되는 표 형태의 도식]`

#### 💻 실습: 레이블 인코딩과 원-핫 인코딩

```python
from sklearn.preprocessing import LabelEncoder
import pandas as pd

# 1. 범주형 데이터 생성
data = {'City': ['Seoul', 'Busan', 'Seoul', 'Daegu', 'Busan']}
df = pd.DataFrame(data)
print("--- 원본 데이터 ---")
print(df)

# 2. 레이블 인코딩 (Label Encoding)
le = LabelEncoder()
df['City_Label'] = le.fit_transform(df['City'])
print("\n--- 레이블 인코딩 결과 ---")
print(df)

# 3. 원-핫 인코딩 (One-Hot Encoding)
# pandas의 get_dummies를 사용하면 매우 간편합니다.
df_onehot = pd.get_dummies(df['City'], prefix='City')
df_final = pd.concat([df, df_onehot], axis=1)

print("\n--- 원-핫 인코딩 결과 ---")
print(df_final[['City', 'City_Busan', 'City_Daegu', 'City_Seoul']])
```

**실행 결과 해석:**
- **레이블 인코딩**: 'Seoul'은 2, 'Busan'은 1, 'Daegu'는 0과 같이 정수로 매핑되었습니다.
- **원-핫 인코딩**: `City_Busan`, `City_Daegu`, `City_Seoul`이라는 3개의 새로운 열이 생겼습니다. 만약 데이터가 'Seoul'이라면 `City_Seoul` 열만 1이 되고 나머지는 0이 됩니다. 이를 통해 모델은 각 도시를 동등한 관계로 인식합니다.

> **⚠️ 초보자가 자주 하는 실수**
> **실수:** 원-핫 인코딩 후 생성된 모든 컬럼을 모델에 그대로 넣는 경우.
> **해결:** 이는 **다중공선성(Multicollinearity)** 문제를 일으킬 수 있습니다. 예를 들어 '성별'이 '남성'과 '여성' 두 가지라면, '남성'이 0이면 자동으로 '여성'은 1이 됩니다. 즉, 한 개의 열만으로도 나머지 정보를 알 수 있어 정보가 중복됩니다. 이를 방지하기 위해 `pd.get_dummies(..., drop_first=True)` 옵션을 사용하여 컬럼 하나를 제거하는 것이 좋습니다.

## 🚀 실무 활용 사례: 고객 이탈 예측 데이터 전처리

실제 현업에서는 위에서 배운 모든 과정이 동시에 일어납니다. 간단한 시나리오를 통해 흐름을 정리해 보겠습니다.

**시나리오: 통신사 고객의 이탈 여부를 예측하는 모델을 만들려고 합니다.**
- **데이터 상태**: 고객의 나이(결측치 있음), 월 이용 금액(이상치 있음), 거주 지역(문자열), 성별(문자열).

**전처리 파이프라인:**
1.  **결측치 처리**: 나이의 빈칸을 전체 고객의 평균 나이로 채웁니다.
2.  **이상치 처리**: 월 이용 금액이 너무 높은(예: 상위 0.1%) 데이터는 기업 고객일 가능성이 높으므로 일반 고객 분석에서는 제거합니다.
3.  **스케일링**: '나이'와 '이용 금액'은 단위가 매우 다르므로, `StandardScaler`를 사용하여 표준화합니다.
4.  **인코딩**: '거주 지역'은 `One-Hot Encoding`으로, '성별'은 `Label Encoding`으로 변환합니다.

이렇게 정돈된 데이터를 모델에 넣어야만 "이용 금액이 급격히 줄어든 30대 서울 거주 남성 고객이 이탈할 확률이 높다"라는 정확한 인사이트를 얻을 수 있습니다.
