# 챕터 5: 데이터 전처리 — "Garbage In, Garbage Out"

머신러닝 모델을 구축하는 과정은 흔히 '마법의 알고리즘'을 찾는 과정이라고 생각하기 쉽습니다. 하지만 실제 데이터 과학자가 업무 시간의 80%를 소비하는 곳은 모델링이 아니라 **데이터 전처리(Data Preprocessing)** 단계입니다. 아무리 세계 최고의 요리사(알고리즘)라도 썩은 재료(지저분한 데이터)를 사용하면 절대 훌륭한 요리(정확한 예측)를 만들 수 없기 때문입니다. 데이터 과학의 세계에서는 이를 "Garbage In, Garbage Out(쓰레기가 들어가면 쓰레기가 나온다)"이라고 부릅니다.

---

## 1. 실생활 비유: 요리 전 재료 손질
최고급 스테이크 요리를 준비하는 과정에 전처리를 비유해 보겠습니다.

1.  **결측치 처리:** 고기 묶음을 샀는데 일부 조각이 빠져 있습니다. 이 상태로 요리하면 양이 맞지 않으므로, 비슷한 부위의 고기로 채워 넣거나 아예 그 묶음을 반품(삭제)해야 합니다.
2.  **이상치 제거:** 고기 속에 갑자기 돌덩이가 섞여 있습니다. 이를 그대로 볶으면 냄비가 망가지고 맛도 이상해지겠죠? 돌덩이는 과감히 골라내야 합니다.
3.  **정규화/표준화:** 소금 한 꼬집(1g)과 고기 한 덩어리(500g)는 물리적 양의 차이가 엄청납니다. 하지만 레시피에서는 '적절한 비율'이 중요합니다. 모든 재료를 '표준 규격'으로 맞추어 레시피에 적용하는 과정입니다.
4.  **인코딩:** 레시피에 "취향에 맞는 소스를 넣으세요"라고 적혀 있습니다. 하지만 요리 로봇은 '취향'이라는 추상적인 말을 이해하지 못합니다. 대신 `소스 A = 1`, `소스 B = 2`라고 숫자로 지정해줘야 로봇이 정확히 움직입니다.

## 2. 직관적 이해: 왜 전처리가 필요한가?
컴퓨터는 기본적으로 거대한 **'숫자 계산기'**입니다. 따라서 다음과 같은 상황이 발생하면 컴퓨터는 계산 불능 상태(Panic)에 빠지거나 잘못된 결론을 내립니다.

*   **데이터가 비어 있을 때:** "계산을 해야 하는데 숫자가 없어요! (Error)" $\rightarrow$ **결측치 처리 필요**
*   **값이 너무 튈 때:** "대부분 10~20인데 갑자기 1억이 나왔어요! 이 값 하나 때문에 평균이 완전히 왜곡돼요!" $\rightarrow$ **이상치 처리 필요**
*   **단위가 서로 다를 때:** "나이는 0~100인데, 연봉은 0~1억이에요. 숫자가 훨씬 큰 연봉이 훨씬 더 중요한 변수라고 착각하겠어요!" $\rightarrow$ **스케일링(정규화/표준화) 필요**
*   **문자가 섞여 있을 때:** "'서울', '부산'이라는 글자를 어떻게 더하고 빼라는 거죠?" $\rightarrow$ **인코딩 필요**

## 3. 기술 설명

### ① 결측치(Missing Value) 처리
데이터가 누락된 상태를 `NaN(Not a Number)`이라고 합니다.
*   **제거(Deletion):** 데이터셋이 충분히 크고 결측치 비율이 낮다면, 해당 행이나 열을 삭제합니다.
*   **대체(Imputation):** 
    *   **평균(Mean):** 데이터 분포가 정규분포에 가까울 때 사용합니다.
    *   **중앙값(Median):** 이상치가 많아 평균이 왜곡되었을 때 사용합니다.
    *   **최빈값(Mode):** 범주형 데이터(문자열)를 채울 때 사용합니다.

### ② 이상치(Outlier) 처리
정상 범위에서 크게 벗어난 값으로, 모델의 일반화 성능을 떨어뜨립니다.
*   **IQR(Interquartile Range) 방식:** 데이터를 4등분 하여 1사분위수($Q1$)와 3사분위수($Q3$)를 구합니다.
    *   $IQR = Q3 - Q1$
    *   범위: $[Q1 - 1.5 \times IQR, Q3 + 1.5 \times IQR]$ 이 범위를 벗어나면 이상치로 판단합니다.

### ③ 스케일링: 정규화 vs 표준화
*   **정규화(Normalization/Min-Max Scaling):** 모든 값을 0과 1 사이로 압축합니다. 데이터의 분포가 균등할 때 유리합니다.
    $$\text{X}_{new} = \frac{X - \min(X)}{\max(X) - \min(X)}$$
*   **표준화(Standardization/Z-score Scaling):** 평균을 0, 표준편차를 1로 만듭니다. 데이터가 가우시안 분포(정규분포)를 따를 때 유리하며, 이상치의 영향에 상대적으로 더 강건합니다.
    $$\text{X}_{new} = \frac{X - \mu}{\sigma}$$

### ④ 인코딩(Encoding)
*   **레이블 인코딩(Label Encoding):** 범주를 단순 숫자로 변환 (예: 사과=0, 배=1, 포도=2). 모델이 $2 > 0$ 이므로 포도가 사과보다 '크다'고 오해할 위험이 있습니다.
*   **원-핫 인코딩(One-Hot Encoding):** 각 범주를 새로운 열로 만들고 해당하면 1, 아니면 0으로 표시합니다. 가짜 순위 관계를 없애주므로 가장 널리 쓰입니다.

## 4. 파이썬 코드 실습

```python
import pandas as pd
import numpy as np
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler

# 1. 지저분한 샘플 데이터 생성
data = {
    'Age': [25, 30, np.nan, 35, 200], # 200은 이상치, nan은 결측치
    'Salary': [5000, 6000, 5500, np.nan, 6200],
    'City': ['Seoul', 'Busan', 'Seoul', 'Incheon', 'Busan']
}
df = pd.DataFrame(data)
print("--- [Step 0] 원본 데이터 ---")
print(df, "\n")

# 2. 결측치 처리 (수치형은 평균값으로 채우기)
imputer = SimpleImputer(strategy='mean')
df[['Age', 'Salary']] = imputer.fit_transform(df[['Age', 'Salary']])
print("--- [Step 1] 결측치 처리 후 ---")
print(df, "\n")

# 3. 이상치 처리 (Age > 100인 경우 중앙값으로 대체)
median_age = df['Age'].median()
df.loc[df['Age'] > 100, 'Age'] = median_age
print("--- [Step 2] 이상치 처리 후 ---")
print(df, "\n")

# 4. 스케일링 (표준화 적용)
scaler = StandardScaler()
df[['Age', 'Salary']] = scaler.fit_transform(df[['Age', 'Salary']])
print("--- [Step 3] 표준화(Standardization) 후 ---")
print(df, "\n")

# 5. 인코딩 (원-핫 인코딩)
df_final = pd.get_dummies(df, columns=['City'])
print("--- [Step 4] 최종 전처리 데이터 ---")
print(df_final)
```

3.  **표준화:** Age와 Salary는 숫자 단위가 완전히 달랐습니다. 표준화를 거치면 두 변수 모두 평균 0, 표준편차 1의 작은 숫자로 변환되어, 모델이 두 변수를 동등한 비중으로 학습합니다.

## 5. 실무 활용 사례: 부동산 가격 예측
실무에서 전처리가 가장 극명하게 성능 차이를 만드는 사례는 **'단위 차이가 큰 변수들이 섞여 있을 때'**입니다.

예를 들어, 집값 예측 모델을 만들 때 **'방의 개수(1~5개)'**와 **'집의 면적(10평~100평)'**이라는 두 변수를 사용한다고 가정해 봅시다. 전처리를 하지 않고 모델에 넣으면, 모델은 숫자의 절대값이 훨씬 큰 '면적' 변수가 '방의 개수'보다 수십 배 더 중요하다고 착각합니다. 결과적으로 방의 개수가 주는 영향력은 완전히 무시되는 현상이 발생합니다. 이때 `StandardScaler`를 적용하면 두 변수가 동일한 스케일 상에 놓이게 되어, 모델이 각 변수의 실제 중요도를 공정하게 학습할 수 있습니다.

## 6. 자주 하는 실수: 데이터 누수 (Data Leakage)
초보 데이터 과학자가 가장 많이 하는 치명적인 실수는 **전체 데이터를 한꺼번에 스케일링하는 것**입니다.

*   **잘못된 방법:** `전체 데이터 스케일링` $\rightarrow$ `Train/Test 분리`
*   **옳은 방법:** `Train/Test 분리` $\rightarrow$ `Train 데이터로 스케일러 학습(fit)` $\rightarrow$ `Train/Test 각각 적용(transform)`

**이유:** 테스트 데이터는 모델이 미래에 만날 '처음 보는 데이터'여야 합니다. 그런데 전체 데이터를 미리 스케일링하면, 테스트 데이터의 최댓값, 최솟값, 평균 정보가 이미 스케일러에 반영되어 학습 데이터에 스며들게 됩니다. 이를 **데이터 누수(Data Leakage)**라고 하며, 학습 시에는 성능이 매우 높게 나오지만 실제 서비스에 배포하면 성능이 뚝 떨어지는 '과적합'의 주범이 됩니다.

## 7. 핵심 요약
*   **결측치:** `SimpleImputer` 등을 이용해 평균/중앙값/최빈값으로 채우거나 삭제한다.
*   **이상치:** IQR 방식 등으로 탐지하여 제거하거나 적절한 값으로 대체한다.
*   **정규화(Min-Max):** 0~1 사이로 변환. 데이터 분포가 균등할 때 유리하다.
*   **표준화(Standard):** 평균 0, 분산 1로 변환. 정규분포일 때 유리하며 이상치에 더 강건하다.
*   **원-핫 인코딩:** 범주형 데이터를 $0$과 $1$의 벡터로 변환하여 가짜 순위 관계를 제거한다.

## 9. 정답 및 해설
1.  **정답:** `MinMaxScaler`는 최솟값과 최댓값을 기준으로 데이터를 압축합니다. 따라서 아주 큰 이상치가 하나만 있어도 나머지 정상 데이터들이 매우 좁은 범위로 뭉쳐버려 변별력이 사라집니다. 반면 `StandardScaler`는 평균과 표준편차를 이용하므로 이상치의 영향을 상대적으로 덜 받습니다.
2.  **정답:** `LabelEncoder`는 범주를 $0, 1, 2, 3$과 같은 숫자로 바꿉니다. 모델은 이를 보고 "AB형(3)이 A형(0)보다 3배 더 크다"라고 잘못된 수치적 관계를 학습할 수 있습니다. `OneHotEncoder`는 각 범주를 독립적인 열로 만들어 이러한 가짜 순위 관계를 없애줍니다.
3.  **정답:** 테스트 데이터의 정보가 학습 과정에 미리 반영되는 현상입니다. 이를 방지하기 위해 반드시 데이터를 먼저 Train/Test 셋으로 나눈 뒤, **Train 셋에서 얻은 통계량(평균, 표준편차 등)만을 사용하여** Test 셋을 변환해야 합니다.
