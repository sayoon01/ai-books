# 챕터 1: 머신러닝이란 무엇인가

# 📘 Chapter 1. 머신러닝이란 무엇인가

머신러닝의 세계에 오신 것을 환영합니다! 머신러닝이라는 도구가 정확히 무엇인지, 그리고 왜 기존의 프로그래밍 방식으로는 한계가 있었는지를 다룹니다. 이 장을 마치고 나면, 여러분은 **"머신러닝은 명시적인 규칙을 프로그래밍하는 것이 아니라, 데이터로부터 규칙을 찾아내는 패러다임의 전환입니다"**라고 자신 있게 말할 수 있게 될 것입니다.

---

### 1. [비유] 요리 레시피 vs 미식가의 감각

**전통적인 프로그래밍**은 **'상세한 요리 레시피'**와 같습니다.
> "소금 5g을 넣고, 3분간 볶은 뒤, 불을 끄세요." 

이렇게 모든 단계를 정확히 지시하면 누구나 같은 맛을 낼 수 있습니다. 하지만 재료의 상태(데이터)가 조금만 바뀌어도(예: 소금이 너무 짜거나 불의 세기가 다르면) 레시피는 제대로 작동하지 않습니다. 사람이 일일이 모든 변수를 계산해서 레시피에 적어야 하기 때문입니다.

**머신러닝**은 **'수많은 요리를 먹어본 미식가가 스스로 레시피를 깨닫는 과정'**과 같습니다.
미식가는 누군가 알려준 레시피 없이도 수천 가지의 맛있는 파스타를 먹어본 뒤, "아, 대략 이 정도의 간과 이 정도의 익힘 정도가 맛있는 파스타의 공통점이구나!"라는 **패턴**을 스스로 찾아냅니다. 이제 새로운 재료가 들어와도 그동안 쌓인 '경험(데이터)'을 바탕으로 어떻게 요리해야 맛있을지 스스로 판단할 수 있게 됩니다.

---

### 2. [직관] 규칙 기반의 한계와 데이터 기반의 등장

우리는 지금까지 컴퓨터에게 "A이면 B를 해라"라고 명령하는 **규칙 기반(Rule-based) 시스템**을 사용해 왔습니다. 하지만 현실 세계의 문제는 너무 복잡해서 모든 규칙을 사람이 직접 작성하는 것이 불가능합니다.

**예를 들어 '개'와 '고양이'를 구분하는 프로그램을 만든다고 가정해 봅시다.**
* **규칙 기반:** "귀가 뾰족하고 수염이 있으면 고양이다." $\rightarrow$ 하지만 귀가 접힌 고양이나, 수염이 긴 개가 나타나면 프로그램은 즉시 오류를 범합니다. 수만 가지의 예외 상황을 모두 `if-else` 문으로 작성할 수 있을까요?
* **머신러닝 기반:** 수만 장의 개 사진과 고양이 사진을 컴퓨터에게 보여줍니다. 컴퓨터는 우리가 알려주지 않아도 "고양이는 대체로 귀의 모양이 이렇고, 눈동자의 패턴이 이렇구나"라는 **특징(Feature)**을 스스로 찾아내어 구분 기준을 만듭니다.

즉, 머신러닝은 **"정답을 알려줄 테니, 정답으로 가는 규칙을 네가 직접 찾아봐!"**라고 컴퓨터에게 권한을 넘기는 패러다임의 전환입니다.

---

### 3. [기술 설명] AI $\rightarrow$ ML $\rightarrow$ DL 그리고 학습의 흐름

#### (1) AI, ML, DL의 관계 (포함 관계)
많은 사람이 이 세 용어를 혼용하지만, 엄격히 말하면 다음과 같은 계층적 포함 관계를 가집니다.
* **인공지능 (Artificial Intelligence):** 인간의 지능을 흉내 내는 모든 기술의 총칭 (가장 넓은 개념)
* **머신러닝 (Machine Learning):** 데이터를 통해 학습하여 성능을 스스로 개선하는 AI의 한 분야
* **딥러닝 (Deep Learning):** 인간의 뇌 구조를 본뜬 '인공신경망(ANN)'을 사용하여 복잡한 패턴을 학습하는 머신러닝의 특수한 기법

> **[도식화]**
> $\text{AI (인공지능)} \supset \text{Machine Learning (머신러닝)} \supset \text{Deep Learning (딥러닝)}$

#### (2) 머신러닝의 기본 프로세스
머신러닝은 크게 두 단계의 파이프라인으로 나뉩니다.

1. **학습 (Training):** 데이터($X$)와 정답($Y$)을 모델에 입력하여, $X$를 $Y$로 만드는 최적의 규칙(함수 $f$)을 찾는 과정입니다.
   - $\text{Input}(X) + \text{Label}(Y) \rightarrow \text{Model} \rightarrow \text{Rule}(f)$
2. **추론 (Inference):** 학습이 완료된 모델(규칙 $f$)에 새로운 데이터($X_{new}$)를 넣었을 때, 정답($Y_{new}$)을 예측하는 과정입니다.
   - $\text{Input}(X_{new}) \rightarrow \text{Rule}(f) \rightarrow \text{Prediction}(Y_{new})$

### 4. 파이썬 코드 실습: 규칙 기반 vs 머신러닝 기반 스팸 필터

단순한 키워드 매칭 방식(규칙 기반)과 데이터 학습 방식(머신러닝 기반)의 차이를 코드로 확인해 보겠습니다.

```python
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB

# 1. 전통적인 규칙 기반(Rule-based) 방식
def rule_based_spam_filter(text):
    # 사람이 직접 정의한 '명시적 규칙'
    spam_keywords = ['광고', '무료', '당첨']
    for word in spam_keywords:
        if word in text:
            return "스팸(Spam)"
    return "정상(Ham)"

# 2. 머신러닝(ML) 기반 방식
# 학습 데이터: (메일 내용, 정답)
train_data = [
    ("오늘 날씨가 정말 좋네요", "정상"),
    ("지금 바로 클릭해서 무료 쿠폰 받으세요", "스팸"),
    ("내일 회의 시간은 2시입니다", "정상"),
    ("축하합니다! 이벤트 당첨되셨습니다", "스팸"),
    ("광고 메일입니다. 읽어주세요", "스팸"),
    ("점심 메뉴 추천 부탁드려요", "정상")
]

# 데이터 분리
texts = [item[0] for item in train_data]
labels = [item[1] for item in train_data]

# 텍스트를 숫자로 변환 (벡터화)
vectorizer = CountVectorizer()
X_train = vectorizer.fit_transform(texts)

# 모델 생성 및 학습
model = MultinomialNB()
model.fit(X_train, labels)

# 테스트 및 결과 비교
test_emails = ["무료 쿠폰 당첨!", "내일 뵙겠습니다", "공짜 선물 드려요"]

print("--- [분류 결과 비교] ---")
for email in test_emails:
    res_rule = rule_based_spam_filter(email)
    
    # ML 모델 추론 과정
    X_test = vectorizer.transform([email])
    res_ml = model.predict(X_test)[0]
    
    print(f"메일: '{email}'")
    print(f"  - 규칙 기반: {res_rule}")
    print(f"  - 머신러닝 기반: {res_ml}")
    print("-" * 30)
```

### 5. 실행 결과 및 해석

**[실행 결과]**
```text
--- [분류 결과 비교] ---
메일: '무료 쿠폰 당첨!'
  - 규칙 기반: 스팸(Spam)
  - 머신러닝 기반: 스팸
------------------------------
메일: '내일 뵙겠습니다'
  - 규칙 기반: 정상(Ham)
  - 머신러닝 기반: 정상
------------------------------
메일: '공짜 선물 드려요'
  - 규칙 기반: 정상(Ham)
  - 머신러닝 기반: 스팸
------------------------------
```

**[결과 해석]**
* **규칙 기반의 한계:** 세 번째 메일인 `'공짜 선물 드려요'`를 보면, 규칙 기반 필터는 '무료', '당첨'이라는 단어가 없기 때문에 이를 **정상 메일로 오판**했습니다. 개발자가 '공짜'라는 단어를 규칙에 추가하지 않는 한, 이 프로그램은 이 메일을 잡지 못합니다.
* **머신러닝의 유연함:** 머신러닝 모델은 '무료'와 '공짜'가 유사한 문맥에서 사용된다는 패턴을 학습 데이터의 분포를 통해 파악합니다. 비록 학습 데이터에 '공짜'라는 단어가 직접적으로 없더라도, 다른 스팸 메일들의 특징을 통해 **확률적으로 스팸일 가능성이 높다고 판단**한 것입니다. 이것이 바로 머신러닝의 핵심인 **'일반화(Generalization)'** 능력입니다.

### 6. 실무 활용 사례

실무에서 머신러닝은 '입력($X$) $\rightarrow$ 모델 $\rightarrow$ 예측($Y$)'의 구조로 다음과 같이 활용됩니다.

1. **콘텐츠 추천 시스템 (Netflix, YouTube):**
   - **입력($X$):** 사용자의 시청 기록, 좋아요 누른 영상, 체류 시간
   - **예측($Y$):** 사용자가 다음에 클릭할 확률이 가장 높은 영상 리스트
2. **금융 이상 거래 탐지 (FDS):**
   - **입력($X$):** 결제 금액, 결제 위치, 평소 결제 패턴, 시간대
   - **예측($Y$):** 해당 거래가 정상 거래인지, 도난 카드를 이용한 부정 거래인지 여부
3. **의료 영상 진단 (AI X-ray):**
   - **입력($X$):** 환자의 흉부 X-ray 이미지 픽셀 데이터
   - **예측($Y$):** 폐렴 또는 결핵 등의 질환 존재 여부 및 확률

### 7. 자주 하는 실수

**❌ "머신러닝만 쓰면 모든 문제가 해결되겠지?"**
머신러닝은 마법의 지팡이가 아닙니다. 데이터가 너무 적거나 일관성이 없다면(**Garbage In**), 아무리 좋은 알고리즘을 써도 엉터리 결과(**Garbage Out**)가 나옵니다. 단순한 규칙으로 해결 가능한 문제는 오히려 전통적인 프로그래밍 방식이 훨씬 빠르고 정확하며 비용이 저렴합니다.

**❌ "딥러닝이 머신러닝보다 항상 좋다?"**
딥러닝은 데이터가 매우 많을 때 강력하지만, 데이터가 적을 때는 오히려 단순한 머신러닝 모델(예: 결정 트리, 랜덤 포레스트)이 더 높은 성능을 내는 경우가 많습니다. 문제의 성격과 데이터의 양에 맞는 도구를 선택하는 것이 엔지니어의 핵심 역량입니다.

---

### 8. 핵심 요약
* **머신러닝**은 명시적인 규칙을 주는 대신, **데이터를 통해 컴퓨터가 스스로 규칙을 찾게 하는 기술**이다.
* **전통적 프로그래밍**은 `데이터 + 규칙 $\rightarrow$ 결과` 구조이고, **머신러닝**은 `데이터 + 결과 $\rightarrow$ 규칙` 구조이다.
* **포함 관계:** $\text{AI} \supset \text{ML} \supset \text{DL}$
* **프로세스:** 학습(Training)을 통해 규칙을 만들고, 추론(Inference)을 통해 결과를 예측한다.

### 9. 확인 문제
**Q. 전통적인 프로그래밍 방식과 머신러닝 방식의 결정적인 차이점은 무엇이며, 왜 현대 사회에서 머신러닝이 필수적인가요?**

**정답 및 해설:** 
전통적인 프로그래밍은 개발자가 직접 **명시적인 규칙(Explicit Rules)**을 정의하여 컴퓨터에게 부여하는 방식입니다. 반면, 머신러닝은 데이터와 그에 대한 정답을 제공하여 컴퓨터가 **스스로 데이터 속의 패턴(Implicit Rules)**을 찾아내게 하는 방식입니다.

머신러닝이 필수적인 이유는 현대 사회의 데이터 양이 폭증했고, 다루어야 할 문제(예: 얼굴 인식, 실시간 번역, 자율주행)가 너무 복잡하여 사람이 일일이 모든 예외 상황과 규칙을 정의하는 것이 불가능하기 때문입니다.
