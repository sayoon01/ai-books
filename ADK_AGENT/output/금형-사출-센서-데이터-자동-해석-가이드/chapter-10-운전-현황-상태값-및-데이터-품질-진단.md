# 10. 운전 현황 상태값 및 데이터 품질 진단

## 운전 현황 상태값의 정의와 분류 체계

본 절에서는 개별 사이클의 분석을 넘어, 특정 금형이나 설비가 현재 어떤 운영 상태에 있는지를 정의하는 '상태값(Status Value)'에 대해 다룹니다. 데이터 사전 관점에서 상태값은 단순한 색상 표시가 아니라, 데이터 수집 장치의 활성화 여부, 센서의 물리적 건전성, 그리고 공정의 가동 주기라는 세 가지 차원의 정보가 결합된 결과물입니다. 각 상태값은 수집된 데이터의 시계열적 분포와 최근 발생한 사이클 타입의 비율을 근거로 결정됩니다.

운전 현황 상태값은 크게 다섯 가지의 색상 코드로 구분되며, 이는 데이터의 '최신성'과 '신뢰성'을 동시에 판정하는 지표로 활용됩니다. 단순히 전원이 켜져 있는 상태를 의미하는 것이 아니라, 실제로 유의미한 데이터가 서버로 전송되고 있으며 그 데이터가 분석 가능한 수준의 품질을 유지하고 있는지를 나타냅니다. 따라서 상태값의 변화는 설비의 물리적 고장이나 공정 스케줄의 변경을 추적하는 핵심 필드가 됩니다.

아래 표는 운전 현황을 구분하는 상태 코드와 그 판정 기준을 정의한 것입니다.

| 상태 코드 | 명칭 | 판정 기준 | 데이터 수집 상태 |
| :--- | :--- | :--- | :--- |
| 🟢 | 운영 중 | 데이터 수집이 정상적으로 이루어지는 상태 | 활성화 (Active) |
| 🟠 | 센서오류 | 최근 30샷 중 50% 이상이 SENSOR_ERROR인 상태 | 활성화 (Warning) |
| 🟡 | 단기 중단 | 최근 6개월 이내에 수집 이력이 없는 상태 | 비활성화 (Inactive) |
| 🔴 | 장기 중단 | 최근 6개월을 초과하여 수집 이력이 없는 상태 | 비활성화 (Inactive) |
| ⬛ | 미운영 | 데이터 수집 이력이 전혀 없는 상태 | 미설정 (None) |

이 표는 개별 사이클의 상태가 아닌 '시스템 전체의 상태'를 정의합니다. 즉, 단일 사이클이 SENSOR_ERROR라고 해서 바로 🟠 상태가 되는 것이 아니라, 일정 구간(30샷) 동안 오류의 빈도가 임계치를 넘었을 때 비로소 상태값이 변경됩니다. 이는 일시적인 노이즈나 단발성 오류로 인해 운영 상태가 빈번하게 변동되는 것을 방지하고, 실질적인 하드웨어 점검이 필요한 시점을 식별하기 위함으로 해석됩니다.

## 최근 30샷 기반의 센서 오류율 해석

운영 중(🟢) 상태에서 센서오류(🟠) 상태로 전환되는 기준인 '최근 30샷 중 50% 이상 오류'는 데이터의 통계적 신뢰 구간을 확보하기 위한 장치입니다. 여기서 '최근 30샷'이란 데이터베이스에 저장된 최신 시점의 사이클 30개를 의미하며, 이 윈도우 내에서 `Cycle Type`이 `SENSOR_ERROR`로 판정된 비율을 계산합니다. 계산식은 다음과 같습니다: Error Rate = (Count of SENSOR_ERROR / 30) × 100.

이 판정 로직에서 50%라는 임계값은 매우 엄격한 기준입니다. 이는 간헐적으로 발생하는 센서 튀기 현상이나 일시적인 통신 불안정으로는 상태값이 변경되지 않음을 의미합니다. 만약 최근 30샷 중 15샷 이상에서 T_MAX=0 또는 P_MAX=0과 같은 치명적 결함이 발견된다면, 이는 단순한 데이터 누락이 아니라 센서 케이블의 단선, 커넥터 접촉 불량, 또는 센서 자체의 소자 파손과 같은 물리적 결함이 발생했을 가능성이 매우 높은 것으로 해석됩니다.

또한, 이 기준은 앞서 정의한 '미장착 센서' 기준과 상호 보완적으로 작동합니다. 특정 채널이 95% 이상 T < 30°C 또는 P < 50bar인 경우 미장착으로 간주하여 `SENSOR_ERROR` 판정에서 제외하므로, 🟠 상태의 전환은 '장착되어 있어야 할 센서가 정상적으로 작동하지 않는 상태'에 집중합니다. 따라서 🟠 상태가 감지되었다면 분석가는 데이터의 수치적 분석을 중단하고, 즉시 하드웨어의 물리적 연결 상태를 점검해야 합니다.

결과적으로 최근 30샷 기반의 오류율 진단은 데이터 품질의 '연속성'을 측정하는 지표입니다. 단일 사이클의 오류는 해당 데이터만 폐기하면 되지만, 🟠 상태로의 진입은 이후 수집될 모든 데이터의 신뢰성이 붕괴되었음을 뜻하므로, 이는 데이터 사전에서 '분석 불능 상태'를 정의하는 가장 강력한 기준이 됩니다.

## 중단 상태(단기/장기)의 시계열적 정의

데이터 수집의 공백 기간에 따라 구분되는 🟡(단기 중단)과 🔴(장기 중단) 상태는 공정 운영의 주기성과 설비 보관 상태를 반영합니다. 여기서 기준이 되는 '6개월'이라는 수치는 일반적인 금형의 유지보수 주기나 생산 계획의 변경 단위를 고려한 설정으로 추정됩니다. 데이터가 수집되지 않는 시점부터 현재 시점까지의 시간 차이(Δ t)를 계산하여 상태를 결정합니다.

단기 중단(🟡)은 0 < Δ t ≤ 6months 범위에 해당합니다. 이는 해당 금형이 현재 생산 라인에서 일시적으로 제외되었거나, 다른 제품 생산을 위해 대기 중인 상태로 해석됩니다. 이 상태에서는 기존에 수집된 데이터의 유효성은 유지되지만, 실시간 모니터링은 불가능한 상태입니다. 분석가는 🟡 상태의 금형을 대상으로 과거 데이터의 경향성을 분석하여, 재가동 시 발생할 수 있는 초기 불량을 예측하는 용도로 데이터를 활용할 수 있습니다.

장기 중단(🔴)은 Δ t > 6months 범위에 해당합니다. 6개월 이상의 공백은 단순한 대기가 아니라, 금형의 장기 보관 또는 공정의 전면적인 변경이 있었음을 시사합니다. 도메인 지식에 비추어 볼 때, 장기간 사용하지 않은 금형은 내부 방청 상태의 변화나 센서의 노후화가 진행되었을 가능성이 큽니다. 따라서 🔴 상태에서 다시 🟢 상태로 복귀할 때는, 이전의 마스터 파형과 현재의 파형 간에 유의미한 차이가 발생할 수 있음을 전제로 데이터를 해석해야 합니다.

마지막으로 미운영(⬛) 상태는 수집 이력 자체가 전무한 상태를 의미합니다. 이는 센서가 장착되지 않았거나, 데이터 수집 시스템이 구축되기 전의 금형, 혹은 시스템에 등록만 되고 실제 데이터 전송이 한 번도 이루어지지 않은 경우입니다. ⬛ 상태는 데이터 사전의 관점에서 '정의되지 않은 필드'와 같으므로, 어떠한 통계적 추론도 수행할 수 없는 상태로 정의합니다.

## 데이터 품질 진단과 운영 상태의 상관관계

운영 상태값은 단순히 현재의 상태를 보여주는 것을 넘어, 수집된 데이터의 '품질 등급'을 결정짓는 선행 지표가 됩니다. 예를 들어, 상태값이 🟢에서 🟠로 빈번하게 교차하는 금형의 데이터는 수치적으로는 `NORMAL` 사이클이 다수 존재하더라도, 데이터의 연속성이 결여되어 있어 시계열 분석의 신뢰도가 낮다고 판단할 수 있습니다.

데이터 품질 진단 시, 분석가는 다음과 같은 상관관계를 고려하여 필드를 해석해야 합니다. 첫째, NORMAL 사이클의 비중이 높더라도 최근 상태값이 🟠라면, 해당 시점의 데이터는 하드웨어 불안정성에 의한 일시적 정상치일 가능성을 배제할 수 없습니다. 둘째, IDLE 사이클이 과도하게 많이 발생하여 운영 상태가 🟢임에도 불구하고 실제 유효 데이터 수가 부족한 경우, 이는 '형식적 운영' 상태로 해석되어야 합니다.

특히 🟡 또는 🔴 상태에서 🟢 상태로 복귀한 직후의 데이터들은 매우 주의 깊게 살펴야 합니다. 앞서 다룬 `WARMUP` 사이클의 빈도가 급증하거나, T_Detect(레진 도달 시간)의 변동 폭이 커지는 경향이 나타날 수 있기 때문입니다. 이는 설비의 열적 평형 상태가 깨진 상태에서 수집된 데이터이므로, 정상 상태(Steady-state)의 데이터와 분리하여 해석하는 과정이 필수적입니다.

결론적으로 운전 현황 상태값은 데이터 사전의 최상위 계층에서 '이 데이터를 믿고 분석해도 되는가'를 결정하는 필터 역할을 합니다. 🟢 상태만이 분석의 기본 전제가 되며, 나머지 상태값들은 데이터의 공백이나 오류의 원인을 규명하는 진단 필드로 기능합니다.

**핵심 요약**
* 운전 현황 상태는 🟢(운영), 🟠(오류), 🟡(단기중단), 🔴(장기중단), ⬛(미운영)의 5단계로 구분하며, 이는 수집의 최신성과 신뢰성을 기준으로 결정된다.
* 센서오류(🟠) 상태는 최근 30샷 중 50% 이상이 `SENSOR_ERROR`일 때 판정하며, 이는 일시적 노이즈가 아닌 물리적 결함이 발생했음을 의미하는 지표로 해석된다.
* 중단 상태(🟡, 🔴)의 기준이 되는 6개월은 공정의 주기성을 반영한 수치이며, 장기 중단 후 복귀 시에는 센서 노후화 및 환경 변화에 따른 데이터 변동 가능성을 고려해야 한다.
