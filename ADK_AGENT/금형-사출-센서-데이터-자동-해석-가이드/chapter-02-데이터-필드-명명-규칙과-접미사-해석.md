# 2. 데이터 필드 명명 규칙과 접미사 해석

## 데이터 필드 명명 규칙과 접미사 해석

사출 성형 공정에서 수집되는 데이터는 수많은 센서로부터 실시간으로 생성되는 시계열 데이터의 집합입니다. 이러한 데이터는 단순히 수치만으로 구성되는 것이 아니라, 특정 시점이나 상태를 나타내는 명명 규칙(Naming Convention)을 통해 그 의미가 결정됩니다. 특히 접미사(Suffix)는 해당 필드가 '언제' 측정되었는지, 혹은 '어떤 성격'의 값인지를 구분하는 결정적인 기준이 됩니다. 만약 접미사에 대한 이해 없이 필드명 앞부분의 접두어(예: T, P)만으로 데이터를 해석할 경우, 시간 데이터를 온도 데이터로 오인하는 등의 심각한 분석 오류가 발생할 수 있습니다. 따라서 본 챕터에서는 데이터 사전의 핵심인 접미사별 정의와 그 도메인적 의미를 상세히 풀이합니다.

## 1. 시점 정의 접미사: _Start와 _End

`_Start`와 `_End`는 특정 공정 단계나 이벤트의 시작과 종료 시점을 기록하는 타임스탬프(Timestamp) 필드에 사용됩니다. 사출 공정은 고정된 순서에 따라 정밀하게 제어되는 시퀀스 공정이므로, 각 단계의 시작과 끝을 명확히 구분하는 것이 공정 사이클 타임을 분석하는 기초가 됩니다. 이 접미사가 붙은 필드는 물리적인 측정값이 아니라 '시간'이라는 차원을 가지며, 일반적으로 시스템의 기준 시간으로부터 경과된 시간을 나타냅니다.

`_Start` 필드는 해당 공정 단계가 트리거된 순간의 시점을 의미합니다. 예를 들어, 수지가 금형 내부로 주입되기 시작하는 시점이나 냉각 공정이 시작되는 시점이 이에 해당합니다. 이 시점은 공정의 정시성을 평가하는 기준점이 되며, 이전 단계의 `_End` 시점과 현재 단계의 `_Start` 시점 사이의 간격을 통해 대기 시간이나 유휴 시간을 산출할 수 있습니다.

`_End` 필드는 해당 공정 단계가 완료되어 다음 단계로 전이되거나, 해당 이벤트가 종료된 시점을 의미합니다. 이는 물리적인 센서 값의 변화나 기계적 리미트 스위치의 작동, 혹은 제어기의 명령 종료 시점을 기준으로 기록됩니다. `_End` 시점의 정확성은 제품의 냉각 시간이나 유지 시간을 결정짓는 핵심 요소가 되므로, 공정 최적화 분석 시 가장 중요하게 다뤄지는 지표 중 하나입니다.

`_Start`와 `_End`의 차이는 해당 단계의 '소요 시간(Duration)'을 의미합니다. 계산식은 `Duration = _End - _Start`로 정의되며, 이를 통해 각 공정 단계별 병목 구간을 찾아낼 수 있습니다. 만약 특정 사이클에서 `_End`와 `_Start`의 간격이 평소보다 길게 측정된다면, 이는 기계적 결함이나 수지의 흐름 정체 등 공정 이상으로 해석될 가능성이 높습니다.

## 2. 정점 값 접미사: _Max

`_Max` 접미사는 하나의 사이클(Cycle) 내에서 측정된 모든 값 중 최댓값을 추출한 필드에 부여됩니다. 사출 공정은 압력과 온도가 급격히 상승했다가 하강하는 동적인 특성을 가지므로, 평균값보다는 정점(Peak) 값이 제품의 품질과 금형의 내구성에 더 직접적인 영향을 미칩니다. 따라서 `_Max` 필드는 해당 사이클의 '강도'나 '최고 부하'를 대표하는 지표로 활용됩니다.

`T_MAX`는 한 사이클 동안 해당 온도 센서에서 측정된 최고 온도를 의미합니다. 이는 수지가 금형 내부에 충전될 때 발생하는 마찰열과 외부 가열 장치에 의한 최고 온도를 나타내며, 수지의 열분해 여부를 판단하는 기준이 됩니다. 만약 `T_MAX`가 0으로 측정된다면, 이는 센서가 정상적으로 작동하지 않았거나 연결에 문제가 발생한 `SENSOR_ERROR` 상태로 판정하는 근거가 됩니다.

`P_MAX`는 한 사이클 동안 측정된 최고 압력을 의미합니다. 사출 압력의 정점은 금형 내부의 밀도를 결정하며, 너무 높을 경우 금형의 손상을 초래하고 너무 낮을 경우 미성형(Short Shot) 결함이 발생할 수 있습니다. `P_MAX` 역시 0으로 측정될 경우, 센서 미장착 혹은 하드웨어 오류로 해석되며, 이는 데이터 필터링 단계에서 제외 대상으로 분류됩니다.

`_Max` 필드의 데이터는 시계열 전체를 분석하지 않고도 해당 사이클의 특성을 빠르게 파악할 수 있게 해주는 요약 통계량의 성격을 가집니다. 분석가는 `_Max` 값을 통해 해당 사이클이 정상 범위 내에 있는지 1차적으로 판단하고, 이상치가 발견되었을 때만 전체 파형 데이터를 확인하는 방식으로 분석 효율을 높일 수 있습니다.

## 3. 도달 시간 접미사: _Detect

`_Detect` 접미사는 본 가이드에서 가장 주의 깊게 다뤄야 할 필드입니다. 일반적인 명명 규칙상 `T`로 시작하는 필드는 온도(Temperature)로 해석하기 쉬우나, `T_Detect`는 온도가 아니라 '레진(수지) 도달 시간'을 의미합니다. 이는 수지가 금형 내부를 흘러가다가 특정 위치에 설치된 센서에 도달하는 순간의 시점을 측정한 값입니다.

`T_Detect`는 수지의 유동성(Fluidity)을 정량적으로 측정하는 지표입니다. 수지의 점도가 낮거나 사출 속도가 빠를수록 `T_Detect` 값은 작아지며, 반대로 점도가 높거나 흐름에 방해 요소가 있을수록 이 값은 커집니다. 따라서 이 필드는 온도 값이 아닌 '시간' 단위로 해석해야 하며, 이를 온도 값으로 오독하여 분석할 경우 완전히 잘못된 결론에 도달하게 됩니다.

`T_Detect` 값이 0으로 기록된 경우는 수지가 센서 위치까지 도달하지 못했음을 의미합니다. 이는 주로 장비 가동 초기 단계에서 수지의 온도가 충분히 올라가지 않아 고점도 상태인 '워밍업(WARMUP)' 단계에서 빈번하게 발생합니다. 따라서 `T_Detect = 0`인 사이클은 분석 대상에서 제외하거나 워밍업 사이클로 별도 분류하여 처리해야 합니다.

도메인 관점에서 `T_Detect`는 제품의 충전 완료 시점과 밀접한 관련이 있습니다. 여러 개의 센서에서 `T_Detect`를 측정할 경우, 각 센서 간의 도달 시간 차이를 통해 금형 내부에서 수지가 균일하게 흐르고 있는지, 혹은 특정 영역에서 정체가 발생하는지를 추론할 수 있습니다. 이는 금형 설계의 적절성을 평가하는 핵심 데이터로 해석됩니다.

## 4. 복합 접미사 및 기타 필드 해석

`_MaxDetect`와 같은 복합 접미사는 `_Max`와 `_Detect`의 의미가 결합된 형태입니다. 이는 여러 채널의 도달 시간 중 최댓값을 의미하거나, 도달 시점 전후로 발생한 최대 피크 값을 의미하는 것으로 추정됩니다. 다만, 소스 자료에 `_MaxDetect`에 대한 명시적인 정의가 제공되지 않았으므로, 분석가는 이를 임의로 단정하지 말고 데이터의 분포와 파형을 통해 그 의미를 역추적해야 합니다.

그 외 `Weight1`, `Quality` 등과 같이 접미사가 없거나 일반적인 명칭으로 구성된 필드들의 경우, 제공된 자료에 상세 설명이 포함되어 있지 않습니다. 이러한 필드들은 임의로 '제품 무게'나 '품질 등급'으로 정의하여 분석에 활용해서는 안 되며, 공식적인 정의가 내려지기 전까지는 '설명 미제공' 상태로 유지하여 데이터 오염을 방지해야 합니다.

필드명에 포함된 숫자(예: T1, T2, P1 등)는 센서의 설치 위치(채널)를 구분하는 식별자입니다. 동일한 접미사(예: `_MAX`)를 가졌더라도 채널 번호에 따라 측정 지점이 다르므로, 금형 도면상의 센서 배치도와 대조하여 각 필드가 금형의 어느 부위(게이트 근처, 말단 부위 등)를 대표하는지 매핑하는 과정이 선행되어야 합니다.

데이터 사전의 관점에서 명명 규칙을 엄격히 적용하는 이유는 분석의 재현성을 확보하기 위함입니다. 분석가마다 `T_Detect`를 온도 혹은 시간으로 다르게 해석한다면, 동일한 데이터셋을 가지고도 서로 다른 결과 보고서가 도출되는 문제가 발생합니다. 따라서 본 가이드에서 정의한 접미사 해석 기준은 모든 분석 단계에서 절대적인 원칙으로 적용되어야 합니다.

## 5. 수치 변환 및 계산식 적용

데이터 수집 시스템에서 저장되는 값은 저장 효율을 위해 정수 형태로 저장되거나 특정 배수로 곱해져 있는 경우가 많습니다. 이를 실제 물리적 단위로 변환하기 위해서는 명확한 계산식을 적용해야 합니다. 특히 시간 관련 필드(`_Start`, `_End`, `T_Detect` 등)는 밀리초(ms) 단위로 저장되는 경우가 많으므로, 이를 초(s) 단위로 변환하는 과정이 필요합니다.

시간 단위 변환식은 다음과 같습니다.
`실제 시간(s) = 필드 값 / 1000`

또한, 전체 사이클 타임 내에서 순수하게 대기하는 시간을 산출하기 위해서는 `CycleInterval` 필드와 공정 단계별 소요 시간을 활용해야 합니다. 사출 공정은 크게 6단계(예: 충전, 보압, 냉각 등)로 구성되는데, 전체 인터벌에서 이 단계들의 합을 제외한 값이 실제 유휴 시간이 됩니다.

`대기 시간(Waiting Time) = CycleInterval - (6단계 공정 시간의 합)`

위 계산식을 통해 도출된 대기 시간이 비정상적으로 길 경우, 이는 `IDLE(유휴)` 사이클로 분류됩니다. 참고 자료에 따르면 `CycleInterval`이 `P75 + (P75-P25)*3` (사분위수 기반 임계치)를 초과하는 경우, 기계 정지나 작업 중단으로 인한 유휴 상태로 해석합니다.

| 접미사 | 의미 | 데이터 성격 | 도메인 해석 (비고) |
| :--- | :--- | :--- | :--- |
| `_Start` | 시작 시점 | 시간 (Timestamp) | 공정 단계의 트리거 시점 |
| `_End` | 종료 시점 | 시간 (Timestamp) | 공정 단계의 완료 시점 |
| `_Max` | 최대치 | 물리량 (Temp, Press) | 사이클 내 최고 부하/강도 |
| `_Detect` | 도달 시간 | 시간 (Time) | 레진이 센서에 도달한 시점 (온도 X) |
| `_MaxDetect` | 최대 도달치 | 미정 | 설명 미제공 (추론 필요) |

**[해석 요약]**
위 표는 필드명의 끝에 붙는 접미사가 데이터의 정체성을 어떻게 변화시키는지를 보여줍니다. 특히 `T_Detect`는 접두어 `T`에도 불구하고 물리량이 아닌 '시간' 데이터임을 명심해야 하며, `_Max` 필드는 센서 오류(`SENSOR_ERROR`)를 판별하는 핵심 지표로 활용됩니다.

## 요약
* `_Start`와 `_End`는 공정의 시작과 끝을 나타내는 시간 데이터이며, 두 값의 차이를 통해 단계별 소요 시간을 산출한다.
* `_Max`는 사이클 내 최고점을 의미하며, `T_MAX`나 `P_MAX`가 0인 경우 센서 오류로 판정하는 근거가 된다.
* `T_Detect`는 온도가 아닌 '레진 도달 시간'을 의미하며, 이 값이 0인 경우 수지가 센서에 도달하지 못한 '워밍업' 상태로 해석한다.
