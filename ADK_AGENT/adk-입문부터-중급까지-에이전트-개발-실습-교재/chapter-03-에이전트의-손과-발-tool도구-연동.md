# 3. 에이전트의 손과 발: Tool(도구) 연동

## 3.1 똑똑한 뇌만으로는 부족한 이유: 비유로 이해하기

여러분은 지금 세상의 모든 책을 읽은 천재 학자를 고용했습니다. 이 학자는 역사, 과학, 철학에 대해 완벽하게 알고 있습니다. 하지만 이 학자에게는 치명적인 약점이 있습니다. 바로 **'방 안에 갇혀 있으며, 전화기나 인터넷이 없다'**는 점입니다.

만약 여러분이 "오늘 서울의 날씨는 어때?"라고 묻는다면, 이 학자는 당황할 것입니다. 그는 '날씨가 무엇인지', '서울이 어디인지'는 잘 알지만, **'지금 현재'**의 데이터에 접근할 방법이 없기 때문입니다. 또한 "내 계좌 잔고를 확인해서 10만 원을 송금해줘"라고 요청해도, 그는 송금하는 방법(이론)은 알지만 실제로 은행 시스템에 접속할 **'손과 발'**이 없습니다.

여기서 **Tool(도구)**은 천재 학자에게 제공하는 '스마트폰', '계산기', '은행 API 접속 권한'과 같습니다. LLM(거대언어모델)이라는 강력한 '뇌'가 추론을 담당한다면, Tool은 그 추론을 현실의 결과로 바꾸는 '실행 수단'이 됩니다.

---

## 3.2 ADK의 Tool 개념 및 용어

ADK(Agent Development Kit)에서 Tool은 에이전트가 외부 세계와 상호작용하기 위해 호출할 수 있는 독립적인 함수나 서비스의 집합입니다.

*   **도구 (Tool):** 에이전트가 특정 목적을 달성하기 위해 실행하는 구체적인 기능 단위입니다. (예: Google Search, DB Query, Email Sender)
*   **도구 정의 (Tool Definition):** LLM이 "이 도구를 언제, 어떻게 사용해야 하는가"를 이해할 수 있도록 제공하는 설명서입니다. 여기에는 도구의 **이름(Name)**, **설명(Description)**, **입력 파라미터(Parameters)**가 포함됩니다.
*   **함수 호출 (Function Calling):** 에이전트가 사용자의 질문을 분석하여 직접 답변하는 대신, "지금은 `get_weather`라는 도구를 `city='Seoul'`이라는 값으로 호출해야겠다"라고 결정하는 과정입니다.
*   **도구 출력 (Tool Output):** 도구가 실행된 후 반환된 결과값입니다. ADK는 이 출력값을 다시 에이전트의 컨텍스트(Context)에 구조적으로 삽입하여, 에이전트가 최종 답변을 생성하도록 돕습니다.

---

## 3.3 왜, 그리고 언제 Tool을 사용하는가? (당위성)

단순히 LLM의 성능이 좋아지면 Tool이 필요 없을까요? 그렇지 않습니다. 엔터프라이즈급 프로덕션 에이전트에서 Tool은 다음과 같은 결정적인 이유로 필수적입니다.

1.  **최신 정보의 반영 (Freshness):** LLM은 학습 데이터의 컷오프(Cut-off) 시점이 있습니다. 실시간 뉴스, 주가, 날씨 등 최신 정보가 필요할 때는 Google Search와 같은 검색 도구가 필수적입니다.
2.  **정확한 계산 및 논리 수행 (Determinism):** LLM은 확률적으로 단어를 생성하므로 복잡한 수학 계산에서 '환각(Hallucination)'을 일으킬 수 있습니다. 이때 계산기나 코드 실행기(Code Interpreter)를 사용하면 100% 정확한 결과를 얻을 수 있습니다.
3.  **기업 내부 데이터 접근 (Private Data):** LLM은 학습하지 않은 기업 내부의 DB나 문서(PDF, Notion 등)에 접근할 수 없습니다. API나 DB 커넥터라는 도구를 통해 보안이 유지된 상태로 데이터를 가져와야 합니다.
4.  **실제 액션 수행 (Actionability):** 정보를 제공하는 것을 넘어, '이메일 발송', '티켓 예약', '서버 재시작'과 같은 실제 물리적/디지털 액션을 수행하려면 반드시 Tool이 필요합니다.

## 3.4 단계별 Python 코드 실습

이번 실습에서는 사용자의 질문에 따라 **'실시간 검색'**을 하거나 **'단순 계산'**을 수행하는 에이전트를 구현합니다. ADK의 구조적 설계를 반영하여 기능을 모듈화하겠습니다.

### 1단계: `tools.py` - 도구 정의 및 구현
LLM이 도구를 이해하려면 **함수의 docstring(설명문)**과 **타입 힌트**가 매우 중요합니다. ADK는 이 정보를 추출하여 LLM에게 전달합니다.

```python
# tools.py

def get_current_weather(city: str):
    """
    특정 도시의 현재 날씨 정보를 가져옵니다.
    Args:
        city: 날씨를 조회할 도시 이름 (예: 'Seoul', 'Tokyo')
    """
    # 실제로는 외부 API(OpenWeatherMap 등)를 호출하지만, 여기서는 시뮬레이션합니다.
    print(f"\n[System] {city}의 날씨 API 호출 중...")
    weather_data = {
        "Seoul": "맑음, 25도",
        "Tokyo": "비, 20도",
        "New York": "흐림, 15도"
    }
    return weather_data.get(city, "날씨 정보를 찾을 수 없는 도시입니다.")

def calculate_expression(expression: str):
    """
    복잡한 수학 수식을 계산합니다.
    Args:
        expression: 계산할 수식 (예: '123 * 456 / 7')
    """
    print(f"\n[System] 수식 계산기 실행 중: {expression}")
    try:
        # 보안상 eval()은 위험하지만, 실습을 위해 사용합니다. 
        # 실제 프로덕션에서는 전용 파서나 라이브러리를 사용하세요.
        return str(eval(expression))
    except Exception as e:
        return f"계산 오류 발생: {str(e)}"

# 에이전트에게 전달할 도구 리스트
AVAILABLE_TOOLS = [get_current_weather, calculate_expression]
```

### 2단계: `agent.py` - 에이전트 설정
에이전트 생성 시 `tools` 파라미터에 정의한 함수 리스트를 전달합니다.

```python
# agent.py
from adk import Agent # ADK 프레임워크 가정

def create_tool_agent():
    # 에이전트의 정체성과 도구 사용 지침을 설정합니다.
    instruction = (
        "당신은 유능한 비서 에이전트입니다. "
        "사용자의 질문에 답하기 위해 필요한 경우 제공된 도구를 사용하세요. "
        "도구 결과가 나오면 이를 바탕으로 친절하게 최종 답변을 작성하세요. "
        "모르는 내용은 추측하지 말고 도구를 통해 확인하세요."
    )
    
    # tools 인자에 tools.py에서 정의한 리스트를 전달합니다.
    agent = Agent(
        name="ToolAssistant",
        instruction=instruction,
        tools=[] # main.py에서 주입할 예정
    )
    return agent
```

### 3단계: `main.py` - 실행 및 테스트
에이전트와 도구를 연결하고 실제로 구동합니다.

```python
# main.py
from agent import create_tool_agent
from tools import AVAILABLE_TOOLS

def main():
    # 1. 에이전트 생성
    my_agent = create_tool_agent()
    
    # 2. 에이전트에 도구 장착
    my_agent.tools = AVAILABLE_TOOLS
    
    # 3. 테스트 케이스
    queries = [
        "서울 날씨는 어때?", 
        "12345 곱하기 6789는 뭐야?",
        "뉴욕 날씨를 알려주고, 거기에 10을 곱하면 얼마인지 계산해줘" # 복합 요청
    ]
    
    for query in queries:
        print(f"\n사용자 질문: {query}")
        response = my_agent.run(query)
        print(f"에이전트 답변: {response}")

if __name__ == "__main__":
    main()
```

## 3.5 핵심 정리

*   **Tool은 LLM의 한계를 극복하는 수단**이며, 최신 정보 접근, 정확한 계산, 외부 액션 수행을 가능하게 합니다.
*   **Tool Definition(이름, 설명, 파라미터)**은 LLM이 어떤 도구를 선택할지 결정하는 핵심 기준이 됩니다. 따라서 설명문을 명확하고 구체적으로 작성해야 합니다.
*   **실행 흐름:** `사용자 질문` → `LLM의 도구 선택(Function Call)` → `코드 실행(Tool Execution)` → `결과값 반환(Tool Output)` → `LLM의 최종 답변 생성`.
*   **ADK의 특징:** ADK는 이러한 Tool 호출 과정과 출력값을 구조화된 컨텍스트로 관리하여 토큰 낭비를 줄이고 추론의 정확도를 높입니다.

## [정답 및 설계 의도]

**A1.** (A): 설명(Description/Docstring), (B): 파라미터(Parameters/Type hints)
*   **설계 의도:** LLM이 코드를 직접 읽는 것이 아니라, 메타데이터를 통해 도구를 식별한다는 원리를 이해했는지 확인합니다.

**A2.** 설명이 너무 짧아(`"데이터를 검색합니다."`) LLM이 이 도구를 언제 써야 할지 모호합니다. 또한 `q`라는 파라미터의 의미가 불분명합니다.
*   **수정안:** `def search_data(query: str): """회사 내부 DB에서 특정 키워드에 해당하는 매출 및 고객 데이터를 검색합니다. Args: query: 검색할 키워드(예: '2023년 매출')"""`
*   **설계 의도:** 도구 정의의 구체성이 에이전트의 성능에 직접적인 영향을 미침을 깨닫게 합니다.

**A3.** 
1. `get_sales_report(month)` : 지난달 매출 데이터를 가져오는 도구
2. `summarize_text(text)` : 긴 텍스트를 요약하는 도구 (또는 LLM 자체 추론 활용)
3. `send_email(recipient, content)` : 이메일을 발송하는 도구
*   **순서:** `get_sales_report` → `summarize_text` → `send_email`
*   **설계 의도:** 복합적인 요청을 개별 도구의 체인(Chain)으로 분해하는 설계 능력을 평가합니다.

**A4.**
1. **비용:** Tool 정의(Description)가 모두 프롬프트(Context)에 포함되므로, Tool 개수가 많아질수록 입력 토큰 수가 증가하여 비용이 상승합니다.
2. **품질:** 선택지가 너무 많으면 LLM이 유사한 기능의 도구 사이에서 혼란을 느껴 잘못된 도구를 호출하는 '도구 선택 오류' 확률이 높아집니다.
*   **설계 의도:** 무조건적인 기능 확장이 아닌, 최적의 도구 세트를 구성하는 설계 관점을 함양합니다.

**A5.** (정답 예시) `ast.literal_eval` 등을 사용하여 안전하게 파싱하고, `try-except` 문에서 에러 메시지를 구체적으로 반환하여 LLM이 이를 인지하고 사용자에게 피드백하도록 구현.
*   **설계 의도:** 실무에서 중요한 보안 이슈를 인지하고, Tool의 에러 출력이 에이전트의 대화 흐름에 어떻게 반영되는지 실습하게 합니다.
