# 4. 대화의 맥락 유지하기: Session과 Memory

## 4.1 기억의 조각들을 맞추는 법: 비유로 이해하기

우리가 누군가와 대화를 나눌 때, 상대방이 "아까 말한 그 문제 말이야..."라고 한다면 우리는 자연스럽게 대화의 앞부분을 떠올립니다. 하지만 컴퓨터에게 대화란 기본적으로 '단발성 요청'의 연속입니다.

많은 초보 개발자들이 대화 맥락을 유지하기 위해 **'단순 문자열 결합'** 방식을 사용합니다. 이는 마치 대화 내용을 전부 커다란 종이에 적어 매번 처음부터 끝까지 다시 읽어주는 것과 같습니다. 대화가 길어지면 종이가 너무 커져서 읽는 데 시간이 오래 걸리고(속도 저하), 결국 종이가 찢어지거나 읽지 못하는 한계(토큰 제한)에 도달합니다.

반면, **ADK의 구조적 컨텍스트 관리**는 숙련된 비서가 '노트'를 작성하는 방식과 같습니다. 비서는 모든 말을 그대로 적지 않습니다. 
- **세션(Session):** 현재 진행 중인 회의록 (현재 대화의 흐름)
- **메모리(Memory):** 고객의 성향, 과거 결정 사항 (장기적으로 기억해야 할 핵심 정보)
- **아티팩트(Artifacts):** 회의 중 생성된 보고서나 데이터 (도구 실행 결과물)

비서는 이 정보들을 구분하여 저장하고, 지금 질문에 꼭 필요한 정보만 골라 모델에게 전달합니다. 이것이 바로 엔터프라이즈급 에이전트가 대규모 대화에서도 효율적으로 작동하는 비결입니다.

---

## 4.2 ADK의 구조적 컨텍스트 개념 (Structural Context)

ADK는 단순한 챗봇을 넘어 '프로덕션 환경'에서 작동해야 하므로, 토큰 효율성과 예측 가능성을 극대화하는 구조를 가집니다.

### 1. 세션 (Session)
세션은 특정 사용자와 에이전트 사이의 **일시적인 대화 단위**입니다. ADK에서 세션은 단순한 메시지 리스트가 아니라, 대화의 상태(State)를 관리하는 컨테이너입니다. 세션이 종료되거나 만료되면 해당 일회성 맥락은 정리됩니다.

### 2. 메모리 (Memory)
메모리는 세션을 넘어 **지속적으로 유지되어야 하는 정보**를 저장합니다. 예를 들어 사용자의 이름, 선호하는 언어, 과거의 특정 선택 등이 여기에 해당합니다. ADK는 메모리를 구조화하여 저장함으로써, 모델이 수만 토큰의 대화 기록을 뒤지는 대신 필요한 정보만 '조회'하도록 돕습니다.

### 3. 구조적 컨텍스트 관리 (Structural Context Management)
단순히 모든 기록을 넣는 것이 아니라, 다음과 같은 최적화 과정을 거칩니다.
- **이벤트 필터링 (Event Filtering):** 불필요한 시스템 로그나 중복된 도구 호출 결과는 제거합니다.
- **요약 (Summarization):** 대화가 길어지면 이전 내용을 요약하여 컨텍스트 윈도우를 확보합니다.
- **아티팩트 관리 (Artifact Management):** 도구가 출력한 대량의 데이터는 전체 대화창에 넣지 않고 별도의 저장소(Artifact)에 둔 뒤, 필요할 때만 참조합니다.

## 4.3 왜 구조적 관리가 필요한가? (당위성)

단순히 `history.append(message)` 방식을 사용하지 않고 ADK의 구조적 관리를 사용해야 하는 이유는 명확합니다.

1. **토큰 비용 최적화 (Cost Efficiency):** LLM의 비용은 입력 토큰 수에 비례합니다. 불필요한 반복 내용을 제거하면 운영 비용을 획기적으로 줄일 수 있습니다.
2. **추론 품질 유지 (Quality/Precision):** 컨텍스트가 너무 길어지면 모델은 중간 내용을 잊어버리는 'Lost in the Middle' 현상을 겪습니다. 핵심 정보만 정제해 제공하면 답변의 정확도가 올라갑니다.
3. **응답 속도 향상 (Latency):** 입력 토큰이 적을수록 모델의 첫 번째 토큰 생성 시간(TTFT)이 단축됩니다.
4. **상태 유지의 일관성 (Consistency):** 사용자가 며칠 뒤에 다시 접속해도 "지난번에 말씀하신 그 프로젝트 말이죠"라고 반응하려면 세션과 분리된 독립적인 메모리 구조가 필수적입니다.

## 4.4 단계별 Python 코드 실습

이번 실습에서는 사용자의 선호도를 기억하고, 이를 바탕으로 맞춤형 추천을 제공하는 '개인화 추천 에이전트'를 구현합니다.

### 1. `tools.py` : 메모리 저장소 역할의 도구
실제 환경에서는 DB에 저장하겠지만, 여기서는 간단한 딕셔너리를 사용하여 메모리 저장소를 시뮬레이션합니다.

```python
# tools.py

# 단순화를 위한 인메모리 저장소 (실제로는 DB 사용)
user_profile_db = {}

def update_user_preference(user_id: str, preference: str):
    """사용자의 선호도를 저장하거나 업데이트합니다."""
    if user_id not in user_profile_db:
        user_profile_db[user_id] = []
    
    user_profile_db[user_id].append(preference)
    return f"사용자 {user_id}의 선호도에 '{preference}'가 추가되었습니다."

def get_user_preferences(user_id: str):
    """사용자의 저장된 모든 선호도를 가져옵니다."""
    prefs = user_profile_db.get(user_id, [])
    if not prefs:
        return "저장된 선호 정보가 없습니다."
    return f"사용자 {user_id}의 선호도: {', '.join(prefs)}"
```

### 2. `agent.py` : 메모리 인지 에이전트 설계
에이전트가 지시문(Instruction)을 통해 메모리를 언제 확인하고 업데이트해야 하는지 정의합니다.

```python
# agent.py
from adk import Agent # ADK 프레임워크 가정

def create_recommendation_agent():
    # 에이전트의 페르소나와 메모리 활용 지침 정의
    instruction = """
    당신은 사용자의 취향을 기억하는 '개인화 추천 전문가'입니다.
    
    [작동 규칙]
    1. 사용자가 자신의 취향이나 좋아하는 것을 말하면 반드시 'update_user_preference' 도구를 사용하여 저장하세요.
    2. 추천을 요청받으면 먼저 'get_user_preferences' 도구를 통해 사용자의 과거 취향을 확인하세요.
    3. 확인된 취향이 있다면 이를 반영하여 맞춤형 추천을 제공하고, 없다면 일반적인 추천을 제공하세요.
    4. 대화의 맥락을 유지하며, 사용자가 '아까 말한 것'이라고 언급하면 세션 내의 이전 대화를 참고하세요.
    """
    
    agent = Agent(
        name="PersonalizedRecommender",
        instruction=instruction,
        model="gemini-1.5-pro" # 또는 지원되는 다른 모델
    )
    return agent
```

### 3. `main.py` : 세션 기반 대화 실행
동일한 세션 내에서의 연속성과, 메모리를 통한 장기 기억을 테스트합니다.

```python
# main.py
from agent import create_recommendation_agent
from tools import update_user_preference, get_user_preferences
from adk import SessionManager

def main():
    # 1. 에이전트 및 세션 매니저 초기화
    agent = create_recommendation_agent()
    agent.register_tools([update_user_preference, get_user_preferences])
    
    session_manager = SessionManager()
    user_id = "user_123"
    
    # 세션 생성 (사용자별 독립된 컨텍스트)
    session = session_manager.create_session(user_id=user_id)

    # 대화 시나리오
    prompts = [
        "안녕! 나는 매운 음식을 정말 좋아해.", # 메모리 저장 유도
        "그리고 나는 커피보다는 차를 즐겨 마셔.", # 메모리 추가 저장 유도
        "나한테 어울리는 저녁 메뉴와 음료를 추천해줄래?", # 메모리 조회 및 활용 유도
        "아까 추천해준 메뉴 말고 다른 건 없어?" # 세션 내 맥락 유지 확인
    ]

    for i, prompt in enumerate(prompts):
        print(f"\n[Turn {i+1}] User: {prompt}")
        # session 객체를 통해 대화하여 구조적 컨텍스트 유지
        response = agent.chat(prompt, session=session)
        print(f"Agent: {response}")

if __name__ == "__main__":
    main()
```

### 🚀 중급자 확장 과제
- **메모리 필터링 구현:** `get_user_preferences`가 너무 많은 데이터를 반환할 때, 최근 3개의 선호도만 추출하여 모델에 전달하는 '필터링 레이어'를 `agent.py`에 추가해 보세요.
- **아티팩트 활용:** 추천 결과 리스트를 단순 텍스트가 아니라 JSON 형태의 '아티팩트'로 저장하고, 다음 턴에서 "그 리스트에서 두 번째 항목만 자세히 알려줘"라고 요청했을 때 아티팩트를 참조하여 답변하도록 구조를 변경해 보세요.

## 4.5 핵심 정리

| 개념 | 설명 | 비유 | 목적 |
| :--- | :--- | :--- | :--- |
| **Session** | 특정 사용자와의 일시적인 대화 흐름 | 현재 진행 중인 회의록 | 단기 맥락 유지 |
| **Memory** | 세션을 넘어 유지되는 구조화된 정보 | 고객 관리 카드 (CRM) | 장기 개인화/연속성 |
| **Structural Context** | 토큰 효율을 위해 정보를 필터링/요약하여 관리하는 방식 | 핵심만 요약한 보고서 | 비용 절감 및 품질 향상 |
| **Artifacts** | 도구 실행 결과 등 대량의 데이터를 별도로 관리하는 객체 | 부록/첨부 파일 | 컨텍스트 오염 방지 |

## [정답 및 설계 의도]

**A1.** (A) 토큰 효율성(또는 비용), (B) Lost in the Middle (또는 컨텍스트 과부하)
- **의도:** 구조적 관리의 근본적인 기술적 이유를 이해하고 있는지 확인합니다.

**A2.** 
1. **맥락 상실:** 각 요청이 독립적으로 처리되어, 이전 턴에서 한 말을 기억하지 못하는 '기억상실' 상태가 됩니다.
2. **상태 관리 불가:** 사용자별로 서로 다른 대화 상태를 유지할 수 없어 멀티 유저 서비스 구현이 불가능합니다.
- **의도:** `Session` 객체의 역할과 상태 유지(Stateful)의 중요성을 파악했는지 확인합니다.

**A3.** **Memory**를 삭제해야 합니다.
- **이유:** `Session`은 현재 대화의 흐름(일시적)인 반면, 프로필 정보는 세션이 종료되어도 유지되는 장기 기억(`Memory`)에 저장되기 때문입니다. 세션만 삭제하면 다음 접속 시 다시 프로필 정보가 나타나게 됩니다.
- **의도:** 세션(단기)과 메모리(장기)의 생명주기 차이를 구분할 수 있는지 확인합니다.

**A4.**
| 항목 | Full Context | Summarized Context |
| :--- | :--- | :--- |
| **속도** | 느림 (입력 토큰 많음) | 빠름 (입력 토큰 적음) |
| **비용** | 높음 (토큰 소모량 증가) | 낮음 (토큰 소모량 최적화) |
| **정확도** | 세부사항은 정확하나 길어지면 혼란 | 핵심은 정확하나 세부 디테일 소실 가능성 |
- **의도:** 엔지니어로서 선택 가능한 전략의 트레이드오프를 분석하는 능력을 배양합니다.

**A5.** 
- **계좌 번호 → Memory:** 사용자가 다시 접속해도 변하지 않는 고유 정보이며, 매번 다시 물어볼 필요가 없는 핵심 정보이기 때문입니다.
- **오늘 상담 내용 → Session:** 해당 상담 회차가 끝나면 휘발되어도 무방하며, 현재의 대화 흐름을 파악하기 위한 일시적 정보이기 때문입니다.
- **의도:** 실제 비즈니스 도메인에 ADK의 메모리/세션 구조를 적절히 매핑할 수 있는지 확인합니다.
