# 2. 첫 번째 에이전트 만들기: Agent의 기본 구조

## 2.1 비유로 이해하기: 신입 사원에게 '직무 기술서' 전달하기

여러분이 회사의 팀장이 되어 새로운 신입 사원을 채용했다고 가정해 보겠습니다. 사원을 책상에 앉혀두고 단순히 "열심히 일하세요"라고 말한다면, 그 사원은 무엇을 해야 할지 몰라 당황할 것입니다. 제대로 된 업무 수행을 위해서는 최소한 다음 세 가지가 필요합니다.

1.  **이름(Name):** "당신은 앞으로 우리 팀의 '고객 응대 담당자'입니다." (정체성 부여)
2.  **능력(Model):** "당신은 외국어 능통자이며, 분석력이 뛰어난 인재군요." (두뇌/역량 결정)
3.  **직무 기술서(Instruction):** "고객의 불만 사항을 접수하면, 먼저 공감해주고, 해결책을 제시한 뒤, 상급자에게 보고하세요." (행동 지침)

ADK에서 에이전트를 만드는 과정도 이와 정확히 같습니다. 단순한 챗봇은 질문에 답하는 '기능'에 집중하지만, **에이전트 설계자**는 에이전트에게 명확한 정체성과 역할, 그리고 행동 규칙을 부여하여 '특정 목적을 수행하는 독립적인 개체'로 정의하는 것부터 시작합니다.

---

## 2.2 ADK 개념 및 용어 (ADK Concepts & Terms)

ADK에서 에이전트의 기본 구조를 정의하는 핵심 요소는 다음과 같습니다.

*   **에이전트(Agent):** 복잡한 다단계 프로세스를 최소한의 인간 개입으로 수행하는 관리형/반복 가능 작업 구조입니다. 단순한 LLM 호출기가 아니라, 설정된 지침에 따라 판단하고 행동하는 주체입니다.
*   **이름(Name):** 에이전트의 고유 식별자입니다. 특히 멀티 에이전트 환경에서는 어떤 에이전트가 어떤 작업을 수행했는지 추적하고 관리하는 데 사용됩니다.
*   **모델(Model):** 에이전트의 '두뇌' 역할을 하는 LLM입니다. ADK는 Gemini뿐만 아니라 다양한 모델을 어댑터를 통해 연결할 수 있는 유연한 모델 연결 구조를 가지고 있어, 작업의 난이도에 따라 경량 모델이나 고성능 모델을 선택해 배치할 수 있습니다.
*   **지시문(Instruction):** 에이전트가 어떻게 행동해야 하는지를 정의한 시스템 프롬프트입니다. 페르소나, 제약 사항, 출력 형식, 작업 순서 등이 포함됩니다. ADK에서는 이를 통해 에이전트의 결정론적 행동을 유도합니다.

## 2.3 왜, 언제 이렇게 설계하는가? (Justification)

단순히 `prompt = "너는 전문가야, 답해줘"`라고 입력하는 것과 `Agent` 클래스를 통해 구조적으로 정의하는 것은 엔터프라이즈 환경에서 큰 차이를 만듭니다.

**1. 예측 가능성(Predictability) 확보**
엔터프라이즈급 에이전트는 매번 다른 답을 내놓는 '창의성'보다, 정해진 규칙을 따르는 '일관성'이 중요합니다. `Instruction`을 통해 제약 사항을 명확히 정의하면 AI의 환각(Hallucination)을 줄이고 예측 가능한 실행 경로를 만들 수 있습니다.

**2. 유지보수의 효율성**
모델이 업데이트되거나(예: Gemini 1.0 → 1.5), 지침이 변경될 때 코드 전체를 수정하는 것이 아니라 `Agent` 설정 파일이나 클래스만 수정하면 됩니다. 이는 '로직'과 '설정'을 분리하는 소프트웨어 공학적 접근입니다.

**3. 확장성(Scalability)**
나중에 에이전트가 10명, 100명으로 늘어날 때, 각 에이전트가 이름과 역할이 명확히 구분되어 있어야만 '오케스트레이션(Orchestration, 여러 에이전트의 협업 관리)'이 가능해집니다.

## 2.4 단계별 Python 코드 실습

가장 단순한 형태의 '기술 문서 요약 에이전트'를 구현해 보겠습니다. 코드는 유지보수를 위해 설정(에이전트 정의)과 실행(메인 로직)을 분리하여 모듈화합니다.

### 1단계: 에이전트 정의하기 (`agent.py`)
이 파일에서는 에이전트의 정체성과 지침을 정의합니다.

```python
# agent.py
from adk import Agent, ModelConfig

# 1. 모델 설정: 사용할 모델과 파라미터를 정의합니다.
# ADK는 어댑터를 통해 다양한 모델을 지원합니다.
model_config = ModelConfig(
    model_name="gemini-1.5-flash", 
    temperature=0.2,  # 낮은 온도는 더 결정론적이고 일관된 답변을 생성합니다.
)

# 2. 에이전트 정의: 이름, 모델, 지시문을 설정합니다.
# 단순한 챗봇이 아니라 '요약 전문가'라는 페르소나를 부여합니다.
summary_agent = Agent(
    name="TechDocSummarizer",
    model=model_config,
    instruction=(
        "당신은 전문 기술 문서 요약 에이전트입니다. "
        "사용자가 제공하는 복잡한 기술 문서를 다음 규칙에 따라 요약하세요: "
        "1. 핵심 개념을 3가지 이내의 불렛 포인트로 정리할 것. "
        "2. 전문 용어는 유지하되, 쉬운 설명을 덧붙일 것. "
        "3. 결론적으로 이 문서가 누구에게 유용한지 한 문장으로 요약할 것. "
        "반드시 한국어로 답변하세요."
    )
)
```

### 2단계: 에이전트 실행하기 (`main.py`)
정의된 에이전트를 불러와 실제로 동작시키는 코드입니다.

```python
# main.py
from agent import summary_agent

def main():
    # 요약할 샘플 기술 문서 내용
    tech_document = """
    ADK(Agent Development Kit) is an open-source framework for building 
    enterprise-grade production agents. Unlike simple prototypes, ADK focuses on 
    structured context management, graph-based architectures for predictable paths, 
    and seamless deployment to Google Cloud environments like Cloud Run and GKE.
    It allows developers to filter unnecessary events and summarize contexts 
    to optimize token usage.
    """

    print(f"--- [{summary_agent.name}] 가 작업을 시작합니다 ---")
    
    # 에이전트에게 메시지 전달 및 응답 수신
    response = summary_agent.run(tech_document)
    
    print(response)
    print("--- 작업 완료 ---")

if __name__ == "__main__":
    main()
```

### [실행 방법]
1. `agent.py`와 `main.py`를 같은 폴더에 저장합니다.
2. 터미널에서 `python main.py`를 실행합니다.

## 2.5 핵심 정리

*   **에이전트의 3요소:** `Name`(식별자), `Model`(두뇌), `Instruction`(행동 지침)으로 구성됩니다.
*   **엔터프라이즈 관점:** 단순 프롬프팅이 아니라 구조화된 `Agent` 클래스를 사용하여 예측 가능성과 유지보수성을 높입니다.
*   **모델 설정:** `temperature`와 같은 파라미터를 통해 에이전트의 창의성 또는 일관성 수준을 조절할 수 있습니다.
*   **모듈화:** 에이전트 정의(`agent.py`)와 실행 로직(`main.py`)을 분리하여 설계하는 것이 ADK의 권장 패턴입니다.

## [정답 및 설계 의도]

**정답 1:** `지시문(Instruction)`
*   **의도:** 에이전트의 핵심 구성 요소인 Instruction의 개념을 정확히 이해했는지 확인합니다.

**정답 2:** 
1.  `temperature=0.9` → `0.1~0.2`로 하향 조정: 금융 데이터는 정확성이 생명이며, 높은 온도는 수치 오류나 환각을 유발할 수 있습니다.
2.  `instruction` 구체화: "분석해서 알려줘"는 너무 모호합니다. 분석 범위, 필수 포함 항목, 금지 사항 등을 명시한 구체적인 직무 기술서 형태로 변경해야 합니다.
*   **의도:** 모델 파라미터(Temperature)와 지시문의 구체성이 결과물에 미치는 영향을 분석할 수 있는지 평가합니다.

**정답 3:** (예시 답안)
`instruction = "당신은 법률 문서 검토 전문가입니다. [제약사항] 절대 법적 자문을 확정적으로 제공하지 말고, 반드시 '법률 전문가와 상담하십시오'라는 문구를 포함하세요. [형식] 1. 위반 가능성이 있는 조항 2. 근거 법령 3. 수정 제안 순으로 작성하세요."`
*   **의도:** 실제 비즈니스 상황에서 발생할 수 있는 리스크(법적 책임 등)를 지시문을 통해 제어하는 설계 능력을 배양합니다.

**정답 4:** 
각 에이전트가 객체화되어 있으면, 오케스트레이터(관리자)가 `agent.name`을 통해 호출 대상을 명확히 지정할 수 있고, 각 에이전트의 `model_config`를 다르게 설정하여(예: 가벼운 작업은 Flash 모델, 무거운 작업은 Pro 모델) 비용과 속도를 최적화할 수 있기 때문입니다.
*   **의도:** 단일 에이전트를 넘어 시스템 전체의 효율성과 확장성을 고려하는 설계 관점을 갖게 합니다.

**정답 5:** (예시 가이드)
`AgentFactory` 클래스 내부에 `dict` 형태로 역할별 지시문을 저장하고, `create_agent` 메서드에서 해당 지시문을 꺼내 `Agent` 객체를 생성하여 리턴하도록 구현하면 됩니다.
*   **의도:** 하드코딩된 설정을 동적 설정으로 변경하는 추상화 과정을 통해 중급 수준의 코드 구조 설계 능력을 키웁니다.
