# 1. AI 에이전트와 ADK 시작하기

## 1.1 비유로 이해하는 AI 에이전트: '친절한 상담원' vs '유능한 비서'

우리는 흔히 챗봇과 AI 에이전트를 혼용해서 부르지만, 이 둘의 결정적인 차이는 **'실행력'**과 **'책임감'**에 있습니다.

*   **단순 챗봇(Chatbot)**은 **'친절한 도서관 상담원'**과 같습니다. 당신이 "제주도 맛집을 알려줘"라고 물으면, 자신이 알고 있는 지식 범위 내에서 최선의 답변을 제공합니다. 하지만 그 맛집을 예약해주거나, 당신의 일정표에 추가해주지는 않습니다. 답변을 주는 것만으로 임무가 끝납니다.
*   **AI 에이전트(AI Agent)**는 **'유능한 개인 비서'**와 같습니다. 똑같이 "제주도 맛집을 예약해줘"라고 요청하면, 에이전트는 다음과 같이 움직입니다. 
    1. 맛집 리스트를 검색합니다(추론).
    2. 당신의 캘린더에서 비어 있는 시간을 확인합니다(도구 사용).
    3. 예약 가능한 식당에 전화를 걸거나 앱으로 예약합니다(실행).
    4. 예약 완료 내역을 당신의 캘린더에 저장하고 알림을 보냅니다(결과 보고).

즉, 챗봇이 **'말하는 존재'**라면, 에이전트는 **'목표를 달성하기 위해 계획을 세우고 도구를 사용하여 작업을 완수하는 존재'**입니다.

## 1.2 ADK 개념 및 핵심 용어

ADK(Agent Development Kit)는 단순한 프로토타입 제작 도구가 아니라, 실제 기업 환경에서 서비스할 수 있는 **엔터프라이즈급 프로덕션 에이전트**를 구축하기 위한 오픈소스 프레임워크입니다.

### 핵심 용어 정리
*   **AI 에이전트(AI Agent):** 복잡한 다단계 프로세스를 최소한의 인간 개입으로 수행하는 관리형/반복 가능 작업 구조입니다.
*   **구조적 컨텍스트 관리(Structured Context Management):** 대화 내용을 단순한 텍스트 뭉치로 저장하는 것이 아니라 세션(Session), 메모리(Memory), 도구 출력(Tool Output), 아티팩트(Artifacts) 등으로 구분하여 관리하는 방식입니다. 이는 불필요한 정보를 필터링하여 토큰 비용을 줄이고 정확도를 높입니다.
*   **그래프 기반 아키텍처(Graph-based Architecture):** ADK 2.0의 핵심으로, 정해진 순서대로 움직이는 '결정론적 코드'와 상황에 따라 판단하는 '적응형 AI 추론'을 결합한 설계 방식입니다. 이를 통해 AI의 예측 불가능성을 제어하고 실행 경로를 예측 가능하게 만듭니다.
*   **모델 어댑터(Model Adapter):** Gemini뿐만 아니라 다양한 외부 모델이나 로컬 모델을 동일한 인터페이스로 연결할 수 있게 해주는 연결 장치입니다.
*   **에이전트 런타임(Agent Runtime):** 구축된 에이전트를 Google Cloud(Cloud Run, GKE 등) 환경에서 즉시 실행하고 배포할 수 있도록 최적화된 인프라 환경입니다.

## 1.3 왜 ADK를 사용해야 하는가? (당위성)

단순히 LLM API를 호출하여 코드를 짜는 것과 ADK라는 프레임워크를 사용하는 것에는 큰 차이가 있습니다.

1.  **토큰 효율성 (Cost & Performance):** 대화가 길어지면 모든 내용을 모델에 전달할 때 비용이 급증하고 모델이 혼란을 느낍니다. ADK는 구조적 컨텍스트 관리를 통해 꼭 필요한 정보만 요약/필터링하여 전달하므로 비용을 최적화합니다.
2.  **예측 가능성 (Reliability):** AI에게 "알아서 해줘"라고 하면 매번 결과가 달라집니다. ADK의 그래프 기반 아키텍처는 중요한 비즈니스 로직은 코드로 고정하고, 유연함이 필요한 부분만 AI에게 맡겨 기업용 서비스에 필수적인 '안정성'을 제공합니다.
3.  **배포의 용이성 (Scalability):** 로컬에서 잘 돌아가는 코드를 서버에 올리는 과정은 고통스럽습니다. ADK는 컨테이너화와 구글 클라우드 원클릭 배포를 지원하여 인프라 설정 시간을 획기적으로 줄여줍니다.

## 1.4 단계별 Python 코드 실습: 첫 번째 에이전트 만들기

이번 실습에서는 아주 간단한 '계산 도구를 사용하는 에이전트'를 만들어 보겠습니다. 코드는 유지보수와 확장을 위해 모듈화하여 구성합니다.

### 1단계: 개발 환경 설정
먼저 ADK 라이브러리를 설치합니다. (가상환경 사용을 권장합니다.)
```bash
pip install adk-framework  # 예시 라이브러리 명칭입니다. 실제 설치 가이드를 따르세요.
```

### 2단계: 도구 정의 (`tools.py`)
에이전트가 사용할 '기능'을 정의합니다.

```python
# tools.py
def calculate_tax(price: float, tax_rate: float = 0.1) -> float:
    """
    상품 가격에 따른 세금을 계산하는 도구입니다.
    Args:
        price: 상품의 가격
        tax_rate: 세율 (기본값 0.1)
    Returns:
        계산된 세금 금액
    """
    return price * tax_rate

# 에이전트가 인식할 수 있도록 도구 리스트를 구성합니다.
AVAILABLE_TOOLS = {
    "calculate_tax": calculate_tax
}
```

### 3단계: 에이전트 설계 (`agent.py`)
에이전트의 정체성과 사용할 도구를 연결합니다.

```python
# agent.py
from adk import Agent, AgentConfig

def create_tax_agent():
    # 에이전트 설정: 모델 및 컨텍스트 관리 방식 정의
    config = AgentConfig(
        model="gemini-1.5-pro", 
        temperature=0, 
        memory_type="structured" # 구조적 컨텍스트 관리 활성화
    )
    
    # 에이전트 생성
    agent = Agent(
        name="TaxAssistant",
        instruction="당신은 세금 계산 전문가입니다. 제공된 도구를 사용하여 정확한 세금을 계산하고 안내하세요.",
        config=config
    )
    
    return agent
```

### 4단계: 실행 메인 루프 (`main.py`)
사용자의 입력을 받고 에이전트를 구동합니다.

```python
# main.py
from agent import create_tax_agent
from tools import AVAILABLE_TOOLS

def main():
    # 1. 에이전트 생성
    tax_agent = create_tax_agent()
    
    # 2. 에이전트에 도구 등록
    tax_agent.register_tools(AVAILABLE_TOOLS)
    
    # 3. 사용자 요청 처리
    user_input = "100,000원짜리 상품의 세금이 얼마인지 계산해줘."
    print(f"사용자 요청: {user_input}")
    
    # 에이전트 실행 (추론 -> 도구 호출 -> 결과 생성)
    response = tax_agent.run(user_input)
    print(f"에이전트 답변: {response}")

if __name__ == "__main__":
    main()
```

### [중급자 확장 과제]
위 코드는 단순한 일회성 실행 구조입니다. 다음 단계로 구조를 변경해 보세요.
*   **상태 유지(Session):** `main.py`에서 `while` 루프를 만들어 사용자와의 대화가 끊기지 않고 이어지도록 세션 기능을 추가해 보세요.
*   **도구 확장:** `tools.py`에 `calculate_discount` (할인 계산) 함수를 추가하고, 에이전트가 '할인 후 세금'을 계산하도록 요청해 보세요.

## 1.5 핵심 정리

*   **AI 에이전트**는 단순 답변을 넘어 목표 달성을 위해 **계획 → 도구 사용 → 실행**의 과정을 거치는 시스템이다.
*   **ADK**는 엔터프라이즈급 구축을 위해 **구조적 컨텍스트 관리**와 **그래프 기반 아키텍처**를 제공한다.
*   **구조적 컨텍스트 관리**를 통해 토큰 효율성을 극대화하고, **모델 어댑터**를 통해 모델 유연성을 확보한다.
*   **배포 최적화** 기능을 통해 Google Cloud 환경으로 빠르게 프로덕션 전환이 가능하다.

## [정답 및 설계 의도]

**A1. 계획, 도구(Tool)**
*(설계 의도: 에이전트의 핵심 정의인 '계획'과 '실행'의 개념을 명확히 구분했는지 확인)*

**A2. 문제점: 1) 토큰 비용 급증, 2) 컨텍스트 윈도우 초과 시 정보 손실 및 환각 발생. / 해결책: ADK의 '구조적 컨텍스트 관리'를 도입하여 세션/메모리를 구분하고 불필요한 이벤트를 필터링/요약하여 전달한다.**
*(설계 의도: 단순 문자열 결합과 구조적 관리의 차이점을 통해 ADK의 도입 당위성을 이해했는지 확인)*

**A3. 예시 답안: 1) 사용자 요청 분석(추론) → 2) 사내 휴가 규정 조회(도구) → 3) 사용자 잔여 연차 확인(도구) → 4) 신청 가능 여부 판단(추론) → 5) 휴가 신청서 작성 및 승인 요청 전송(도구) → 6) 결과 안내(추론)**
*(설계 의도: 실제 비즈니스 프로세스를 에이전트의 작업 단위로 쪼개어 생각하는 설계 능력을 배양)*

**A4. 추천 로직(법적 기준) 부분은 '결정론적 코드(Deterministic Code)'로 고정하여 경로를 강제하고, 고객 응대 부분은 '적응형 AI 추론(Adaptive Reasoning)'에 맡겨 유연하게 대응하도록 설계한다.**
*(설계 의도: 결정론적 코드와 적응형 추론의 결합이라는 그래프 아키텍처의 핵심 가치를 실제 사례에 적용하는지 확인)*

**A5. 특정 시간 대량 처리 → Cloud Run (서버리스 특성상 요청이 없을 때 비용이 0이며, 필요 시 빠르게 확장 가능). / 24시간 실시간 응대 → GKE (지속적인 트래픽 처리에 최적화되어 있으며, 세밀한 클러스터 제어 가능).**
*(설계 의도: 에이전트의 워크로드 특성에 맞는 배포 인프라를 선택하는 아키텍처 관점의 사고력 측정)*
