# 8. 종합 — 이 데이터로 무엇을 읽을 수 있는가

## 사출 한 샷의 디지털 트윈: 식별자부터 공정 시간까지의 유기적 결합

지금까지 우리는 개별 필드들이 각각 무엇을 측정하고 어떤 단위를 가지는지 세부적으로 살펴보았습니다. 하지만 데이터 분석의 실무적 관점에서 가장 중요한 것은 개별 필드의 정의를 아는 것을 넘어, 이 모든 필드가 유기적으로 결합하여 하나의 '사출 샷(Shot)'이라는 물리적 사건을 어떻게 정량적으로 기술하고 있는지를 이해하는 것입니다. 데이터셋의 한 행(Row)은 단순한 숫자들의 나열이 아니라, 실제 현장에서 일어난 한 번의 사출 사이클을 디지털 공간에 그대로 옮겨놓은 '디지털 트윈'의 단면이라고 해석해야 합니다.

이 데이터 모델은 [식별 및 조건 필드 $\rightarrow$ 온도 및 압력 센서 필드 $\rightarrow$ 공정 시간 필드]로 이어지는 논리적 흐름을 가지고 있습니다. 먼저 Model, Resin, Condition, Sequence와 같은 식별 및 조건 필드들은 해당 샷이 어떤 환경에서 생성되었는지를 정의하는 '기준점(Baseline)' 역할을 합니다. 어떤 재료를 사용했는지, 어떤 금형 조건에서 찍어냈는지를 먼저 확정 지어야만, 이후에 측정되는 센서 값들이 정상 범위 내에 있는지 혹은 이상 징후를 보이는지를 판단할 수 있는 기준이 생기기 때문입니다.

그다음으로 T1~8과 P1~8 계열의 센서 데이터들은 기준점 위에서 실제로 벌어진 '물리적 상태'를 기록합니다. T*_Start부터 T*_End, T*_Max로 이어지는 온도 변화와 P*_Max, P*_MaxDetect로 대표되는 압력의 정점 및 도달 시점은 레진이 금형 내부를 채우고 굳어가는 역동적인 과정을 수치화한 것입니다. 이는 정적인 상태가 아니라, 사출이라는 물리적 이벤트가 진행됨에 따라 실시간으로 변하는 상태 값을 특정 시점별로 압축하여 기록한 결과물입니다.

마지막으로 ProcessTime1~6으로 이어지는 공정 시간 필드들은 이 모든 물리적 변화가 어떤 '타임라인' 위에서 전개되었는지를 결정합니다. 사출(Fill)부터 보압(Pack), 냉각(Cool), 형개(Opening), 취출(Ejecting), 형폐(Closing)에 이르기까지 각 단계에 소요된 시간은 센서 데이터의 변화 속도와 밀접하게 연관되어 있습니다. 예를 들어 냉각 시간(ProcessTime3_Cool)이 평소보다 짧아졌다면, 이는 온도 센서의 End 값이나 Max 값에 직접적인 영향을 미칠 수밖에 없습니다.

결국 데이터셋의 한 행은 '어떤 조건(Baseline)에서, 어떤 물리적 상태(State)를 거쳐, 얼마만큼의 시간(Timeline)이 소요되었는가'라는 세 가지 차원의 정보가 하나의 벡터로 압축된 형태입니다. 분석가는 이 유기적 결합 구조를 이해함으로써, 특정 필드의 이상치가 발견되었을 때 그것이 단순한 센서 오류인지, 아니면 조건의 변경이나 공정 시간의 변동으로 인해 발생한 물리적 결과물인지를 입체적으로 추적할 수 있게 됩니다.

## 데이터 해석의 경계: '필드 정의'와 '통계적 인사이트'의 명확한 구분

데이터 분석을 처음 접하는 담당자가 가장 흔히 범하는 오류 중 하나는 '필드의 의미를 아는 것'과 '데이터를 통해 인사이트를 도출하는 것'을 동일한 단계로 생각하는 것입니다. 하지만 이 가이드가 제공하는 '필드 해석'은 분석의 최종 목적지가 아니라, 분석을 시작하기 위해 반드시 거쳐야 하는 '최소한의 전제 조건'입니다. 필드 해석(What it is)과 통계 분석(What it means) 사이에는 엄격한 층위의 구분이 필요합니다.

필드 해석의 영역은 'T1_Start는 사출하기 전 금형의 온도이며 단위는 ℃이다'라는 사실을 정의하는 것입니다. 이는 제공된 필드 설명 자료에 근거한 객관적인 사실(Fact)의 영역이며, 누구에게나 동일하게 적용되어야 하는 절대적인 기준입니다. 만약 이 단계에서 정의가 잘못되어 T1_Detect를 온도로 해석하거나 ProcessTime을 초 단위로 오인한다면, 이후에 수행되는 모든 통계적 분석은 기초부터 무너진 '가짜 분석'이 됩니다. 즉, 필드 해석은 데이터라는 원재료의 성분을 분석하는 작업과 같습니다.

반면, 통계 분석의 영역은 'T1_Start의 변동성이 제품의 치수 불량률에 어떤 영향을 미치는가' 또는 'P1_Max 값이 특정 임계치를 넘었을 때 불량이 발생하는가'를 찾아내는 과정입니다. 이는 정의된 필드들을 조합하여 상관관계를 분석하고 인과관계를 추론하는 인사이트(Insight)의 영역입니다. 이 단계에서는 분석가의 가설과 통계적 기법이 동원되며, 결과값은 데이터의 분포와 패턴에 따라 달라질 수 있습니다. 

따라서 분석가는 자료에 근거한 '사실(Fact)'과 자신의 분석적 '추론(Inference)'을 명확히 구분하여 기록해야 합니다. "자료에 따르면 T*_Detect는 레진 도달 시간이다"라는 문장은 사실이지만, "T*_Detect의 시간이 길어지는 것은 레진의 유동성이 낮아졌기 때문으로 추정된다"라는 문장은 추론입니다. 사실과 추론을 섞어서 기술하면, 나중에 분석 결과에 오류가 발견되었을 때 그것이 데이터 정의의 오해에서 비롯된 것인지, 아니면 추론 과정의 논리적 결함에서 비롯된 것인지 구분할 수 없게 됩니다.

요약하자면, 본 가이드는 데이터 스키마라는 '지도'를 읽는 법을 알려주는 것입니다. 지도를 읽을 줄 알아야 목적지까지 가는 경로를 설계(분석)할 수 있듯이, 필드 정의에 대한 완벽한 숙지가 선행되지 않은 상태에서 수행하는 통계 분석은 지도 없이 낯선 땅을 헤매는 것과 다름없습니다. 분석의 깊이는 화려한 통계 기법이 아니라, 데이터 하나하나가 가진 물리적 의미를 얼마나 정확하게 꿰뚫고 있느냐에서 결정됩니다.

## 데이터 핸들링 시 반드시 지켜야 할 3가지 주의사항

필드 해석 가이드를 숙지했더라도, 실제 데이터를 전처리하고 분석하는 과정에서 무의식적으로 범하기 쉬운 실수들이 있습니다. 특히 금형 사출 데이터는 측정 시점과 단위가 매우 까다롭기 때문에, 다음의 세 가지 주의사항을 데이터 핸들링의 철칙으로 삼아야 합니다.

첫째, 공정 시간 필드(ProcessTime1~6)의 단위 변환 누락을 극도로 경계해야 합니다. 참고 자료에 명시된 바와 같이, ProcessTime 계열 필드들은 수집된 원시 값에서 1,000을 나누어야 비로소 우리가 이해하는 '초(second)' 단위가 됩니다. 만약 이 변환 과정을 누락한 채 분석을 진행한다면, 모든 공정 시간이 1,000배 뻥튀기되어 계산됩니다. 이는 단순한 수치 오류를 넘어, 다른 시간 기반 필드(예: CycleInterval)와의 정합성을 깨뜨려 전체 타임라인 분석을 불가능하게 만드는 치명적인 결과로 이어집니다. 따라서 데이터를 로드하는 즉시 가장 먼저 수행해야 할 작업은 ProcessTime 필드들의 단위 변환입니다.

둘째, 접미사에 따른 측정 시점과 데이터 타입의 오독을 방지해야 합니다. 특히 T*_Detect와 P*_MaxDetect 필드는 이름에 'T(Temperature)'와 'P(Pressure)'가 포함되어 있어, 입문자들은 이를 온도나 압력 값으로 오해하는 경우가 매우 많습니다. 하지만 이 필드들은 명확히 '레진이 해당 센서에 도달한 시간(초)'을 측정한 값입니다. 온도/압력 필드와 시간 필드가 한 데이터셋에 섞여 있기 때문에, 컬럼명만 보고 판단하지 말고 반드시 접미사의 의미를 재확인해야 합니다. 시점의 오독은 엉뚱한 변수들을 묶어 상관분석을 수행하게 만들어, 물리적으로 불가능한 결론을 도출하게 하는 주범이 됩니다.

셋째, 설명이 제공되지 않은 필드에 대한 임의 해석을 엄격히 금지해야 합니다. 본 데이터셋에는 Weight1, Weight2, Quality, Worker와 같이 설명란에 '-'로 표기된 필드들이 존재합니다. 분석 과정에서 이러한 필드들이 유용해 보인다는 이유로 "Weight는 아마 제품의 무게일 것이다"라거나 "Quality는 합격/불합격 여부일 것이다"라고 임의로 정의하여 분석에 포함시키는 행위는 매우 위험합니다. 데이터 정의가 불분명한 필드를 분석에 사용할 경우, 잘못된 전제 위에 세워진 가설이 전체 분석의 신뢰도를 떨어뜨리게 됩니다. 설명이 없는 필드는 '설명 미제공'으로 명시하고, 공식적인 확인이 이루어지기 전까지는 분석 대상에서 제외하는 것이 데이터 분석의 기본 원칙입니다.

| 주의 항목 | 핵심 체크포인트 | 발생 가능한 오류 |
| :--- | :--- | :--- |
| **단위 변환** | ProcessTime $\div$ 1,000 $\rightarrow$ 초(sec) | 공정 시간의 1,000배 과다 계산 |
| **시점 오독** | T*_Detect, P*_MaxDetect $\rightarrow$ 시간 데이터 | 온도/압력 값으로 오인하여 분석 |
| **임의 해석** | '-' 표기 필드 $\rightarrow$ 사용 금지/확인 필요 | 근거 없는 가설에 기반한 잘못된 결론 |
| **결론** | **데이터의 물리적 성격을 정확히 구분하여 처리해야 함** | |

## 결론: 데이터는 공정의 거울이다

결국 금형 사출 센서 데이터의 각 필드를 해석하는 작업은, 보이지 않는 금형 내부에서 벌어지는 물리적 현상을 데이터라는 거울을 통해 투영해 보는 과정입니다. 식별자부터 온도, 압력, 그리고 공정 시간에 이르기까지 모든 필드는 서로 독립적인 숫자가 아니라, 하나의 사출 샷이 완성되기까지의 일련의 과정을 정밀하게 기록한 조각들입니다. 이 조각들을 정확한 위치에 맞추어 조립할 수 있을 때, 비로소 데이터는 단순한 수치에서 '공정의 언어'로 변모하게 됩니다.

데이터 스키마에 대한 정확한 이해가 없는 분석은 '쓰레기를 넣으면 쓰레기가 나온다(Garbage In, Garbage Out)'는 말처럼, 아무리 정교한 통계 모델을 사용하더라도 결국 잘못된 결론이라는 쓰레기를 출력할 뿐입니다. 본 가이드를 통해 익힌 필드 해석 관점을 바탕으로 데이터셋을 바라본다면, 이제는 단순한 엑셀 시트의 컬럼이 아니라 실제 현장에서 레진이 흐르고, 압력이 가해지며, 냉각되어 제품이 빠져나오는 물리적 흐름이 보이기 시작할 것입니다. 정확한 해석이 전제된 분석만이 현장의 문제를 해결하고 공정을 최적화하는 실질적인 열쇠가 될 수 있음을 명심하시기 바랍니다.

***

**핵심 정리**
*   **데이터의 유기적 결합:** 한 행의 데이터는 [기준 조건 $\rightarrow$ 물리적 상태 $\rightarrow$ 시간 흐름]이 결합된 하나의 '사출 샷'이라는 물리적 사건의 디지털 기록이다.
*   **해석과 분석의 구분:** '필드가 무엇인가(Fact)'를 정의하는 해석 단계와 '무엇을 의미하는가(Insight)'를 찾는 분석 단계는 엄격히 구분되어야 하며, 해석이 선행되어야 분석이 가능하다.
*   **3대 주의사항:** ProcessTime의 1,000 나누기 변환, Detect 계열 필드의 '시간' 속성 파악, 설명 미제공 필드의 임의 해석 금지를 반드시 준수해야 한다.
